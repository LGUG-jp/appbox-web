お役立ちアプリBOX / CSV差分チェッカー v1.2.2
==========================================

現在の共通assets版: v1.4.1（Issue #97）。アプリ固有版: v1.2.2（Issue #83）。
過去の変更履歴に記載された共通assets版は当時の記録です。

本ツール自体の機能版数は、AppBox全体および共通assetsの版数とは別に管理します。
AppBox全体のリリース履歴はappbox\README.md / CHANGELOG.mdを参照してください。
共通assetsの仕様・版数はappbox\assets\README.txtを参照してください。


■ 1. 概要


2つのCSVファイルをブラウザ内で比較し、行の追加・削除・変更・一致を
確認するための庁内向けツールです。

選択されたCSVファイルは、クライアント端末のブラウザ内で処理されます。
CSVデータをサーバーへ送信・保存する処理や、外部サービスへの通信処理は
ありません。


■ 2. 動作環境


サーバー:
- Windows Server
- IIS

クライアント:
- Microsoft Edge

本ツールはHTML、CSS、JavaScriptで動作します。
CSV比較処理にPHPやデータベースは使用しません。


■ 3. 構成ファイル


- index.html: 比較画面のHTML
- csvdiff.css: 比較画面のアプリ固有スタイル
- csvdiff.js: CSVの読込み、比較、表示および出力処理
- help.html: 利用者向けヘルプ
- samples/: 動作確認用の新旧CSVサンプル
- LICENSE.txt / NOTICE.txt: ライセンスおよび第三者著作物の表示
- ../../assets/: AppBox共通のスタイル


■ 4. 配置・初期設定


IISの「お役立ちアプリBOX」のapps配下に csvdiff フォルダーを作成し、
このフォルダー内に index.html、csvdiff.css、csvdiff.js と help.html を
配置してください。

配置例:

  appbox/
    index.html
    assets/
    apps/
      qrcode/
      schedule/
      textdiff/
      csvdiff/
        index.html
        csvdiff.css
        csvdiff.js
        help.html
        LICENSE.txt
        NOTICE.txt
        samples/

本ツールの比較画面は、HTML、CSS、JavaScriptをそれぞれ index.html、
csvdiff.css、csvdiff.js に分離して管理します。

ただし、ヘッダーの共通部品とヘルプ画面は、お役立ちアプリBOX共通の
アセットを使用します。

index.htmlが読み込む共通ファイル:

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-components.css

index.htmlが読み込むアプリ固有ファイル:

- ./csvdiff.css
- ./csvdiff.js

help.htmlが読み込む共通ファイル:

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-help.css

重要:
appbox\assets\を同時に配置しないと表示が崩れます。
本ツールだけを単独で切り出して配置することはできません。
詳細はappbox\assets\README.txtを参照してください。

共通CSSは必ずアプリ固有のcsvdiff.cssより前に読み込みます。
共通CSSはCSSカスケードレイヤー（@layer appbox）を使用しており、
レイヤーに属さないcsvdiff.cssが常に優先されます。
そのため共通CSSを追加しても既存画面の見た目は変わりません。

利用者向けの説明はhelp.htmlです。
README.txtは管理者・保守担当者向け資料であり、
一般利用者向けのリンク先には使用しません。


■ 5. 主な機能と仕様


● 主な機能

- 左側を旧CSV、右側を新CSVとして比較
- 利用者によるキー列の選択
- キーの並び順に依存しない行比較
- 追加、削除、変更、一致の件数集計
- 変更セルのハイライト表示
- 比較対象列の選択
- 差分のみ、全件、状態別の表示切替
- キー、セル値および元CSV行番号の検索
- 元の順序、差分優先、キー昇順・降順による並べ替え
- ページング（25件、50件、100件、200件）
- 差分CSVの保存
- UTF-8およびShift_JISの読込み
- 文字コードの自動判定
- カンマ、タブ、セミコロン区切りの自動判定
- 区切り文字の手動指定
- CR、LF、CRLFの各改行コードに対応
- 引用符、区切り文字、改行を含むCSVセルに対応
- 比較時の値の正規化
- 列ごとの差分件数の集計
- 変更箇所がある列だけを表示
- 新旧CSVの元行番号を表示
- 変更された列による行の絞り込み
- サンプルデータを内蔵
- ドラッグ＆ドロップによるファイル選択

● 入力CSVの条件

- ファイル拡張子は .csv としてください。
- 1行目を列名（ヘッダー）として扱います。
- ファイルサイズの上限は20MBです。
- データ行数の上限は200,000行です。
- 列数の上限は300列です。
- 総セル数の上限は2,000,000セルです。
- 対応文字コードはUTF-8およびShift_JISです。
- UTF-16、EUC-JP等は対象外です。
- 対応する区切り文字はカンマ、タブおよびセミコロンです。
- 空の列名は使用できません。
- 重複する列名は使用できません。
- 各データ行の列数は、ヘッダーの列数と一致している必要があります。
- 閉じられていない引用符があるCSVは読み込めません。
- 引用符で囲むフィールドは、フィールドの先頭を引用符で開始してください。
- 引用符で囲んだフィールド内に引用符を含める場合は、引用符を2つ連続して
  記述してください。
- 閉じ引用符の後には、区切り文字、改行またはファイル終端のみを
  記述できます。
例:
  "鈴木, 次郎"  → セル内のカンマとして読み込みます。
  "a""b"        → a"b として読み込みます。

● 比較上の注意

- キー列には、各行を一意に識別できる列を選択してください。
- キー列が空欄の行がある場合、比較を停止して該当行を表示します。
- キー列に重複値がある場合、比較を停止して値と該当行を表示します。
- キー列以外の比較対象列を1列以上選択する必要があります。
- 比較条件を設定しない場合、キー値およびセル値は文字列の完全一致で
  比較します。
- 前後空白、大文字・小文字、全角・半角、改行等の違いも、
  対応する正規化条件を有効にしない限り差分として扱います。
- 比較条件で値を正規化した場合、キー列にも同じ正規化条件を適用します。
- 正規化後にキー値が空欄または重複となった場合、比較を停止します。
- 列名の前後空白は除去して扱います。
- 新CSVと旧CSVで列の並び順が異なっていても、同じ列名で対応付けます。
- 片方にのみ存在する列は、該当側を「列なし」として比較します。
- 行の並び順が異なっていても、キー列の値で対応付けます。
- ヘッダーのみでデータ行がないCSVも読み込めます。
- 複数列を組み合わせた複合キーには対応していません。

● 比較条件（値の正規化）

比較条件を設定すると、値を正規化した上で一致または差分を判定します。

正規化は比較判定のみに使用します。
結果画面および差分CSVには、正規化前の元の値を表示・出力します。

利用できる比較条件:

1. セルの先頭・末尾の空白を無視する
   値の先頭および末尾にある空白を除去して比較します。

   例:
     「総務課」と「 総務課 」を一致として扱います。

2. 連続するスペース・タブを1つとして扱う
   半角空白、タブおよび全角空白が連続している部分を、1つの半角空白に
   統一して比較します。

   例:
     「山田  太郎」と「山田 太郎」を一致として扱います。

3. 英字の大文字・小文字を同じ文字として扱う
   英字を小文字に統一して比較します。

   例:
     「ABC」と「abc」を一致として扱います。

4. 全角英数字・記号・空白と半角の違いを同じ文字として扱う
   全角英数字、全角記号および全角空白を、対応する半角文字に変換して
   比較します。

   例:
     「ＡＢＣ１２３」と「ABC123」を一致として扱います。

5. セル内の改行の種類の違いを同じものとして扱う
   CRLF、CRおよびLFをLFに統一して比較します。

6. 日付の書き方が違っても同じ日付として扱う
   年、月、日が明確に解釈できる日付を YYYY-MM-DD 形式に統一して
   比較します。

   対象例:
     2026/4/1
     2026-04-01
     2026.4.1
     2026年4月1日

   上記はすべて「2026-04-01」として比較します。

7. 数値の書き方が違っても同じ数値として扱う
   数値として明確に解釈できる値について、桁区切りや不要な符号、
   小数点以下のゼロ等を正規化して比較します。

   例:
     「1,000」と「1000」を一致として扱います。
     「1.0」と「1」を一致として扱います。

注意:
- 数値表記の統一を有効にすると、「001」と「1」も一致として扱われます。
  職員番号、自治体コード、郵便番号等、先頭ゼロに意味がある列を
  キーや比較対象にする場合は注意してください。
- 数値変換で安全に扱えない非常に大きな値では、意図しない丸めが生じる
  可能性があります。
- 比較条件はキー列にも適用されるため、正規化によって別のキーが
  同一になることがあります。
- 複数の比較条件を有効にした場合は、画面に示された処理順序で
  組み合わせて適用します。
- 比較条件を変更すると、以前の比較結果を破棄します。
  条件を確認した上で、再度「差分を比較」ボタンを押してください。

● 文字コード

自動判定では、次の順序で文字コードを判定します。

1. UTF-8として厳格に読み込みます。
2. UTF-8として読み込めない場合、Shift_JISとして読み込みます。
3. いずれでも読み込めない場合、エラーを表示します。

文字化けが発生する場合は、文字コードを手動で選択してください。
文字コードを変更するとCSVを再解析し、以前の比較結果を破棄します。

注意:
Windows上で「Shift_JIS」と呼ばれるCSVには、Windows-31JまたはCP932に
固有の文字が含まれる場合があります。業務で使用する文字については、
Microsoft Edge上で事前に表示確認してください。

● 区切り文字

カンマ、タブおよびセミコロンに対応しています。

選択できる設定:
- 自動判定
- カンマ
- タブ
- セミコロン

自動判定では、CSV先頭部分に含まれる区切り文字候補の出現状況を基に
区切り文字を決定します。

区切り文字を手動指定した場合は、指定した文字でCSVを解析します。
区切り文字を変更すると、読込み済みのCSVを再解析し、以前の比較結果を
破棄します。

注意:
- 特殊な形式や、先頭行に複数種類の区切り文字候補が含まれるCSVでは、
  自動判定が正しく行われない場合があります。
- 自動判定で列数等の解析結果が正しくない場合は、区切り文字を
  手動で指定してください。
- 通常のカンマ区切りCSVの利用を推奨します。

● 差分の区分

追加:
  正規化後のキーが新CSVにのみ存在する行

削除:
  正規化後のキーが旧CSVにのみ存在する行

変更:
  正規化後のキーが新旧両方に存在し、選択した比較対象列のいずれかが
  比較条件適用後に異なる行

一致:
  正規化後のキーが新旧両方に存在し、選択した比較対象列がすべて
  比較条件適用後に一致する行

● 元CSV行番号

比較結果には、旧CSVおよび新CSVの元の行番号を表示します。

- 1行目は見出し行です。
- 最初のデータ行は2行目として表示します。
- 追加行では旧CSV行番号を「—」と表示します。
- 削除行では新CSV行番号を「—」と表示します。
- 変更行および一致行では、新旧両方の行番号を表示します。
- 行番号は検索対象に含まれます。
- 差分CSVにも旧CSV行番号および新CSV行番号を出力します。
- 結果表では、旧CSV行番号、新CSV行番号の順に表示します。

注意:
行番号は、読み込んだCSV上の論理的なレコード位置を示します。
セル内に改行を含むCSVでは、テキストエディター等で表示される
物理的な行番号とは一致しない場合があります。

● 列ごとの差分件数

比較結果の上部に、比較対象列ごとの変更件数を表示します。

集計対象:
- 状態が「変更」の行
- 新旧両方に同じキーが存在する行
- 比較条件適用後に値が異なる列

追加行および削除行は、列ごとの差分件数には含めません。
これは、追加・削除行を全列分加算すると、既存行における変更傾向を
把握しにくくなるためです。

例:

  所属  12件
  内線  35件
  更新日 8件

件数が0件の列も表示します。

● 変更列フィルター

「変更列」から列名を選択すると、その列に差分がある行だけを
表示します。

例:
「所属」を選択した場合、所属列が変更された行を表示します。

判定:
- 変更行では、選択した列が実際に変更された行を表示します。
- 追加行および削除行では、比較対象列を差分として扱うため、
  選択した列についても表示対象になります。
- 一致行は変更列を持たないため、列を指定した場合は表示されません。

「すべての列」を選択すると、変更列による絞り込みを解除します。

状態フィルター、検索および変更列フィルターは組み合わせて使用できます。

● 「変更箇所だけ表示」

「変更箇所だけ表示」にチェックを入れると、結果表に表示する比較対象列を、
現在の検索・状態・変更列フィルターに該当する行の中で差分がある列だけに
絞り込みます。

常に表示される列:
- キー列
- 状態
- 旧CSV行番号
- 新CSV行番号


例:
比較対象列が「氏名、所属、内線、更新日」で、現在の表示対象行では
「所属」と「内線」にだけ差分がある場合、結果表には次を表示します。

- キー列
- 状態
- 旧CSV行番号
- 新CSV行番号
- 所属の新旧値
- 内線の新旧値

注意:
- この機能は、行を絞り込むものではなく、表に表示する列を
  絞り込む機能です。
- 各行ごとに表示列を変えるのではなく、現在の表示対象行全体で
  差分がある列を表示します。
- 追加行または削除行が表示対象に含まれる場合、それらの行では
  比較対象列すべてを差分として扱うため、原則として全列が表示されます。
- 変更箇所を確認する用途では、状態を「変更のみ」に設定して使用すると
  効果が分かりやすくなります。
- 表示対象となる変更列がない場合は、その旨を画面に表示します。
- この設定は差分CSVの出力列には影響しません。

● 検索・フィルター・並べ替え

検索:
- キー値
- 新旧CSVのセル値
- 新CSV行番号
- 旧CSV行番号

状態フィルター:
- 差分のみ
- すべて
- 追加のみ
- 削除のみ
- 変更のみ
- 一致のみ

変更列フィルター:
- すべての列
- 比較対象として選択した各列

並べ替え:
- 元の順序
- 差分を先頭
- キー昇順
- キー降順

「元の順序」では、旧CSVの行順を基本とし、旧CSVに存在しない追加行を
その後に新CSVの順序で表示します。

● 差分CSVの保存

差分CSVには、一致を除いた追加、削除、変更の各行を出力します。

出力内容:
- 状態
- キー列
- 旧CSV行番号
- 新CSV行番号
- 比較対象列ごとの旧CSVの値
- 比較対象列ごとの新CSVの値

出力形式:
- 文字コード: UTF-8 BOM付き
- 区切り文字: カンマ
- 改行コード: CRLF
- ファイル名: csv差分_YYYY-MM-DD.csv

出力対象:
- 追加
- 削除
- 変更

出力対象外:
- 一致

注意:
- 画面上の検索、状態フィルター、変更列フィルターおよび
  「変更箇所だけ表示」の設定にかかわらず、一致以外の全差分を出力します。
- 正規化は比較判定のみに使用し、差分CSVには正規化前の元の値を
  出力します。
- 比較対象列は、画面で選択したすべての列を出力します。

安全対策:
セル値が空白または制御文字に続いて、次の文字から始まる場合は、
表計算ソフトで数式として解釈される危険を低減するため、
先頭にアポストロフィを付加します。

  =
  +
  -
  @

このため、保存した差分CSVの一部の値は、入力CSVの値に対して
先頭にアポストロフィが追加される場合があります。

● 処理性能上の注意

CSVの解析、比較、検索、集計、絞り込みおよび並べ替えは、
クライアント端末上で実行します。

上限以内のCSVでも、行数や列数が多い場合は、端末性能によって
処理に時間がかかる場合があります。処理中は画面上に
「CSVを処理しています」と表示します。

本ツールの処理は主にブラウザのメインスレッドで実行されるため、
大容量CSVの処理中にMicrosoft Edgeが一時的に応答しにくくなる場合が
あります。

比較条件を複数有効にすると、完全一致での比較より処理量が増加します。

● エラーとなる主な条件

次の条件では、CSVの読込みまたは比較を停止してエラーを表示します。

- 拡張子が .csv ではない
- ファイルサイズが20MBを超えている
- データ行数が200,000行を超えている
- 列数が300列を超えている
- 総セル数が2,000,000セルを超えている
- CSVにデータが存在しない
- 空の列名がある
- 列名が重複している
- データ行の列数がヘッダーと一致しない
- 引用符が閉じられていない
- 引用符がフィールドの途中にある
- 閉じ引用符の後に、区切り文字、改行またはファイル終端以外の文字がある
- 文字コードを判定または復号できない
- 選択した区切り文字でCSVを正しく解析できない
- 新旧CSVに共通する列名がない
- キー列に空欄がある
- キー列に重複値がある
- 正規化後のキー列に空欄がある
- 正規化後のキー列に重複値がある


■ 6. データの取扱い


選択したCSVはブラウザのメモリ内で読み込み、比較します。
サーバーへのアップロード、データベースやブラウザ保存領域への保存、
外部サービスへの送信は行いません。差分CSVは利用者が保存操作を
行った場合にだけ端末へ出力します。


■ 7. セキュリティとプライバシー


- CSVデータはブラウザ内で処理します。
- CSVデータをサーバーへアップロードまたは保存しません。
- CSVデータを外部サービスへ送信しません。
- 外部CDN、外部API、Webフォント等は使用しません。
- 外部JavaScriptライブラリには依存しません。
- 画面表示時にCSV由来の文字列をHTMLエスケープします。
- 出力CSVには、表計算ソフトで数式として解釈される代表的な
  先頭文字への対策を実施します。
- ファイルサイズ、行数、列数および総セル数に上限を設けています。
- ファイル差替えやクリア時には、古い比較結果を破棄します。
- 文字コード、区切り文字、キー列、比較対象列または比較条件を
  変更した場合は、以前の比較結果を破棄します。
- 非同期処理の世代管理により、古い読込み処理が後から結果を
  上書きすることを防止しています。

注意:
ブラウザ内処理であっても、機密情報や個人情報を含むCSVは、所属組織の
情報セキュリティポリシーおよびデータ取扱規程に従って使用してください。


■ 8. アクセシビリティと操作性


- ファイル選択、検索、絞り込み等の入力にはlabelまたはaria-labelを設定しています。
- エラーにはrole="alert"、警告と処理中表示にはrole="status"とaria-liveを使用します。
- 処理中はaria-busyを更新し、比較結果はキーボードでフォーカスできます。


■ 9. 既知の制約


- 複数列を組み合わせた複合キーには対応していません。
- UTF-16およびEUC-JPには対応していません。
- 対応する区切り文字はカンマ、タブおよびセミコロンに限られます。
- CSV文法のすべてを厳格に検証するものではありません。
- 検索、集計および並べ替えは、データ量によって時間がかかる場合があります。
- 比較処理を途中で明示的に中止するボタンはありません。
- 正規化ルールを列ごとに個別設定することはできません。
- 正規化ルールはキー列を含むすべての比較値に共通して適用します。
- 日付の正規化は、年月日を含む対応形式に限られます。
- 和暦、日時、Excelシリアル値等の日付変換には対応していません。
- 数値の正規化では、JavaScriptの数値として扱える範囲を使用します。
- 非常に大きな整数や高精度小数では、意図しない丸めが生じる可能性が
  あります。
- 元CSV行番号は論理レコードの位置です。セル内改行がある場合、
  テキスト上の物理行番号とは一致しない場合があります。
- 列ごとの差分件数には、追加行および削除行を含めません。
- 変更列フィルターでは、追加・削除行の比較対象列を差分として扱います。
- 「変更箇所だけ表示」で追加・削除行を含めると、原則として
  比較対象列すべてが表示されます。
- 差分CSVには、画面上の検索、フィルターおよび列表示設定にかかわらず、
  一致以外の全差分を出力します。


■ 10. 運用・保守


HTML内のmeta要素に加え、IISのHTTPレスポンスヘッダーでも
必要なセキュリティ設定を行ってください。

推奨例:
- Cache-Control: no-store
- X-Content-Type-Options: nosniff
- Referrer-Policy: no-referrer
- Content-Security-Policy
- frame-ancestors 'none' または X-Frame-Options: DENY
- Permissions-Policy

比較画面のCSSおよびJavaScriptは同一サーバー上の外部ファイルへ分離済みです。
Content-Security-Policyで script-src 'self' および style-src 'self' を
指定する場合は、共通資源を含むすべての参照先が同一オリジンで配信されることを
確認してください。
