お役立ちアプリBOX / 画像かんたん加工  v1.2.2
==========================================

現在の共通assets版: v2.1.0。アプリ固有版は v1.2.2 です。
過去の変更履歴に記載された共通assets版は当時の記録です。


本ツール自体の機能版数は、AppBox全体および共通assetsの版数とは別に管理します。
AppBox全体のリリース履歴はappbox\README.md / CHANGELOG.mdを参照してください。
共通assetsの仕様・版数はappbox\assets\README.txtを参照してください。


■ 1. 概要


JPEG、PNG、WebP画像をブラウザ内で加工するための庁内向けツールです。

「1枚ずつ加工」モードでは、トリミング、リサイズ、回転、反転、
黒塗り、モザイク、文字・図形による注釈、形式変換および容量調整を
行えます。

黒塗り、モザイク、文字、四角形、楕円、矢印は編集可能なレイヤーとして
管理されます。保存前であれば、加工箇所の移動、サイズ変更、表示・非表示、
順序変更、設定変更および削除ができます。

「複数画像を一括処理」モードでは、複数画像へ共通のリサイズ、回転、
形式変換、容量調整、文字透かしおよびファイル名変更を適用し、
処理後の画像と処理結果CSVをZIPファイルとして保存できます。

読み込んだ画像はクライアント端末のブラウザ内で処理されます。
本ツールには、画像をサーバーまたは外部サービスへ送信する処理は
ありません。


■ 2. 動作環境


サーバー:
- Windows Server
- IIS

クライアント:
- Microsoft Edge

画像の処理性能、読込み可能形式および保存可能形式は、
Microsoft EdgeのCanvas機能、画像デコーダー、画像エンコーダー、
端末のメモリ容量等に依存します。

WebP等の選択形式へ正しく変換できなかった場合は、
異なる拡張子で保存せず、エラーを表示します。


■ 3. 構成ファイル


- index.html: 画像加工画面
- image.css: アプリ固有のスタイル
- image.js: 画像読込み、加工、出力処理
- help.html: 利用者向けヘルプ
- ../../assets/: AppBox共通のスタイル


■ 4. 配置・初期設定


IISの「お役立ちアプリBOX」配下に画像加工ツール用のフォルダーを作成し、
次の4ファイルを配置してください。

- index.html
- help.html
- image.css
- image.js

配置例:

  appbox/
    index.html
    assets/
    apps/
      qrcode/
      schedule/
      textdiff/
      csvdiff/
      imageedit/
      index.html
      help.html
      image.css
      image.js

お役立ちアプリBOXの入口ページから、画像加工ツールのフォルダーへ
リンクしてください。

本ツールは外部CDN、外部API、Webフォント、外部JavaScriptライブラリ等を
使用しません。CSSおよびJavaScriptは、同一サーバー上のファイルを
読み込みます。

index.htmlが読み込む共通ファイル:

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-components.css

help.htmlが読み込む共通ファイル:
本体のimage.cssには依存しません。

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-help.css
- ../../assets/appbox-help.js

重要:
「../../assets/」はお役立ちアプリBOX共通のアセットです。
appbox\assets\を同時に配置しないと表示が崩れます。
本ツールだけを単独で切り出して配置することはできません。
詳細はappbox\assets\README.txtを参照してください。

共通CSSは必ずimage.cssより前に読み込みます。
共通CSSはCSSカスケードレイヤー（@layer appbox）を使用しており、
レイヤーに属さないimage.cssが常に優先されます。
そのため共通CSSを追加しても既存画面の見た目は変わりません。

利用者向けの説明はhelp.htmlです。
README.txtは管理者・保守担当者向け資料であり、
一般利用者向けのリンク先には使用しません。


■ 5. 主な機能と仕様


● 対応画像形式

読込み:
- JPEG（.jpg / .jpeg）
- PNG（.png）
- WebP（.webp）

保存:
- JPEG
- PNG
- WebP

一括処理:
- 元画像と同じ形式
- JPEGへ統一
- PNGへ統一
- WebPへ統一

非対応:
- HEIC / HEIF
- GIF
- BMP
- TIFF
- SVG
- RAW画像
- アニメーション画像

注意:
拡張子が対応形式でも、ファイルが破損している場合や、実際の内容が
対応画像ではない場合は読み込めません。

● 1枚ずつ加工モード

次の加工・操作を行えます。

秘匿加工:
- 黒塗り範囲
- モザイク範囲
- 黒塗りブラシ
- モザイクブラシ
- ブラシ幅の変更
- モザイクサイズの変更

注釈:
- 文字
- 四角形
- 楕円
- 矢印
- 注釈色の変更
- 文字サイズの変更
- 線幅の変更

画像操作:
- 自由範囲のトリミング
- 指定比率によるトリミング
- トリミング範囲の数値指定
- 左90度回転
- 右90度回転
- 左右反転
- 上下反転
- ピクセル数を指定したリサイズ
- 縦横比を維持したリサイズ

出力:
- JPEG、PNG、WebPへの形式変換
- JPEGの透明部分を白または黒で合成
- 目標容量に合わせた自動調整
- 保存ファイル名の変更
- 定型プリセットの適用

確認・履歴:
- 読込み時と現在の加工結果の比較プレビュー
- 加工箇所の一覧表示
- 1つ戻す
- やり直す
- 読込み時の状態へ戻す

● 編集可能レイヤー

次の加工は、保存するまで編集可能なレイヤーとして管理されます。

- 黒塗り範囲
- モザイク範囲
- 黒塗りブラシ
- モザイクブラシ
- 文字
- 四角形
- 楕円
- 矢印

レイヤーに対して行える操作:
- 画像上で選択
- ドラッグによる移動
- 選択枠右下のハンドルによるサイズ変更
- 加工設定の変更
- 表示・非表示の切替
- 上下の順序変更
- 個別削除

保存時は、表示中のレイヤーだけを画像へ焼き込みます。
非表示のレイヤーは保存画像へ反映されません。

注意:
レイヤーは本ツール内だけの編集情報です。
保存したJPEG、PNGまたはWebPに、編集可能なレイヤー情報は残りません。

● レイヤーの描画仕様

元画像、確定済み加工レイヤー、選択枠等の操作表示は、
それぞれ別のCanvasで管理します。

- 元画像用Canvas
- 加工レイヤー用Canvas
- 選択枠・トリミング枠・作成中プレビュー用Canvas

この構成により、モザイクブラシ等の追加時に、それ以前の黒塗り、
注釈または他のモザイクが消えないようにしています。

モザイクは元画像を基に生成します。
レイヤーの上下順序を変更すると表示上の重なり順は変わりますが、
モザイクそのものは、下位の注釈や黒塗りを再度モザイク化するものでは
ありません。

● トリミング

トリミングツールを選択すると、画像上にトリミング枠と、
画像直下に確定用の操作バーが表示されます。

トリミング枠の操作:
- 枠の内側をドラッグして移動
- 四隅のハンドルをドラッグしてサイズ変更
- 枠外からドラッグして新しい枠を作成
- X、Y、横幅、高さを数値で指定
- 枠を中央へ配置
- 初期枠へ戻す
- キャンセル

範囲が決まったら、画像直下の
「この範囲で切り抜く」ボタンで確定します。

トリミング確定後は、元画像と各加工レイヤーの座標および範囲を
新しい画像サイズに合わせて調整します。

トリミング枠自体は一時的な操作情報であり、通常の加工レイヤーとしては
保存しません。

● トリミング比率

次の比率を選択できます。

- 自由
- 1:1
- 4:3
- 16:9
- 3:4
- 35:45
- 読込み時の元画像比率

注意:
証明写真の寸法、比率、画素数、背景、顔の位置等の要件は、
手続きや提出先によって異なります。

本ツールの比率選択肢は作業補助のための例であり、
提出要件への適合を保証するものではありません。
必ず提出先の規定を確認してください。

● モザイクおよび黒塗り

範囲ツール:
画像上の対象範囲をドラッグし、長方形の加工レイヤーを作成します。

ブラシツール:
画像上を自由になぞり、ストローク単位の加工レイヤーを作成します。

モザイク:
- 指定したブロックサイズで画像を粗く表示します。
- ブロックサイズは保存前に変更できます。
- 元画像を基にモザイク画像を生成します。

黒塗り:
- 指定範囲またはブラシの軌跡を黒色で塗りつぶします。
- 保存画像へ黒色のピクセルとして焼き込まれます。

注意:
保存前および保存後に画像を目視確認し、個人情報、車両番号、
文書内容等が確実に判別できない状態になっていることを確認してください。

モザイクは対象や設定によって元の内容を推測できる場合があります。
確実な秘匿が必要な箇所には、対象より十分に広い範囲を黒塗りすることを
推奨します。

● 注釈

次の注釈を追加できます。

- 文字
- 四角形
- 楕円
- 矢印

設定可能な項目:
- 文字内容
- 色
- 文字サイズ
- 線幅

追加した注釈は、保存前であれば移動、サイズ変更、設定変更、
順序変更、表示・非表示の切替および削除ができます。

● 比較プレビュー

「読込み時と現在を比較」ボタンを押すと、
次の画像を左右に並べて確認できます。

- 読込み時の元画像
- 現在の加工結果

現在の加工結果には、表示中のレイヤーを合成した状態が反映されます。

トリミング、回転またはリサイズを行った場合は、
元画像と現在画像で構図や寸法が異なることがあります。

個人情報等を秘匿する場合は、保存前に比較プレビューでも
加工漏れがないことを確認してください。

● 定型プリセット

単体処理および一括処理で、次のプリセットを選択できます。

- Web掲載用
- メール添付用
- 庁内文書貼付用
- サムネイル用
- 原寸・メタデータ除去

プリセットは、用途に応じて出力形式、長辺、目標容量等を設定します。

注意:
プリセットは一般的な作業を補助する初期値です。
掲載先、メール環境、文書システム等の個別要件への適合を
保証するものではありません。

● 画像サイズおよび容量の上限

ブラウザのメモリ枯渇や応答停止を防止するため、
次の上限を設けています。

1ファイル:
- 最大容量: 25MB
- 最大幅: 8,192px
- 最大高さ: 8,192px
- 最大総画素数: 36,000,000画素

一括処理:
- 最大枚数: 30枚
- 合計容量: 150MB
- 1ファイルの最大容量: 25MB
- 各画像の最大幅、高さおよび総画素数は単体処理と同じ

上限を超える画像は読み込まないか、一括追加時にスキップします。

上限以内であっても、画像の寸法、枚数、圧縮形式、加工レイヤー数、
端末性能等によっては処理に時間がかかる場合があります。

● リサイズ

1枚ずつ加工する場合は、横幅と高さをピクセル単位で指定できます。

「縦横比を維持」が有効な場合は、一方を変更すると、
もう一方を自動計算します。

一括処理では、次の方法を選択できます。

- 長辺を指定ピクセル以下にする
- 指定した最大横幅・最大高さの範囲内に収める
- 横幅を指定する
- 高さを指定する
- リサイズしない

「元画像より大きくしない」を有効にすると、
元画像より小さい指定でない限り拡大しません。

● 目標容量の自動調整

目標容量を有効にすると、指定容量以下になるよう画像を自動調整します。

JPEG / WebP:
- 画質を段階的に調整します。
- 最低画質でも目標容量を超える場合は、出力画像の寸法を縮小します。

PNG:
- 画質設定による調整は行いません。
- 目標容量を超える場合は、出力画像の寸法を縮小します。

最小出力寸法まで調整しても目標容量を達成できない場合は、
画像を保存した上で「目標容量未達」として警告します。

単体処理:
- 実際の出力容量
- 出力寸法
- 目標容量の達成または未達

を画面上に表示します。

一括処理:
- 画像一覧
- 最終集計
- 処理結果CSV

に目標容量未達を記録します。

注意:
目標容量は必ず達成できるものではありません。

● 一括処理

一括処理では、複数画像へ共通設定を適用し、
画像と処理結果CSVをZIPファイルとして保存します。

主な機能:
- 最大30枚まで追加
- 合計150MBまで追加
- 最大160pxの軽量サムネイルによる一覧表示
- 共通リサイズ
- 共通回転
- 共通形式変換
- 画像ごとの容量調整
- 文字透かし
- ファイル名の文字列置換
- 接頭辞および接尾辞の追加
- 連番名への置換
- ZIP名の変更
- 処理中止
- 最後に作成したZIPの再保存
- 処理結果CSVの出力

処理中は、画像の追加、削除、一覧消去、設定変更およびモード切替を
一時的に無効化します。

一括処理では、トリミング、モザイク、黒塗り、図形注釈等の
画像ごとの個別加工は行いません。
これらが必要な場合は「1枚ずつ加工」モードを使用してください。

● 一括文字透かし

一括処理では、各画像へ共通の文字透かしを追加できます。

設定項目:
- 透かし文字
- 配置位置
- 透明度
- 文字サイズ
- 色

配置位置:
- 左上
- 右上
- 左下
- 右下
- 中央
- 中央斜め

文字サイズは画像の短辺に対する割合で指定します。

透かしを無効にしている場合は、透かし文字、透明度および文字サイズは
処理条件として使用しません。

● 一括処理の中止

一括処理中は「処理を中止」ボタンを使用できます。

中止操作を行った場合、現在処理中の画像が完了した後に停止します。
処理中のエンコードを直ちに強制終了するものではありません。

中止前までに成功した画像と、全件の処理状況を記録したCSVは、
ZIPファイルとして保存します。

処理結果は次のいずれかで記録されます。

- 成功
- 成功（目標容量未達）
- 失敗
- 未処理

● ファイル名の取扱い

出力ファイル名には、Windowsで使用できない文字や、
パスとして解釈される文字を無害な文字へ置き換えます。

主な対象:
- バックスラッシュ
- スラッシュ
- コロン
- アスタリスク
- 疑問符
- ダブルクォート
- 山括弧
- 縦線
- 制御文字
- 連続するピリオド
- 末尾のピリオドおよび空白
- Windows予約名
  - CON
  - PRN
  - AUX
  - NUL
  - COM1～COM9
  - LPT1～LPT9

出力時にファイル名が変更される場合があります。

ZIP内で同じファイル名が重複した場合は、
「-2」「-3」等を付けて区別します。

● ZIPファイル

一括処理後の画像と処理結果CSVは、無圧縮ZIPとして保存します。

JPEG、PNG、WebPは既に圧縮された画像形式であるため、
ZIP内部での追加圧縮は行いません。

ZIP内のファイル名:
- UTF-8で保存
- ZIPのUTF-8フラグを設定
- Windowsで使用できない代表的な文字を置換
- パス区切り文字を置換
- 連続するピリオドを無害化
- Windows予約名を無害化
- 同名ファイルへ連番を付与
- ファイル名の長さを制限

ZIP作成中は、処理中のファイル名と進捗を画面に表示します。

注意:
ZIP生成では画像データをブラウザのメモリ上へ展開します。
画像枚数や容量、端末性能によっては処理に時間がかかる場合があります。


■ 6. データの取扱い


● 処理結果CSV

一括処理で作成するZIPには「処理結果.csv」を含めます。

記録項目:
- 元ファイル名
- 結果
- 出力ファイル名
- 出力幅
- 出力高さ
- 出力容量（byte）
- 目標容量達成
- エラー

CSVはUTF-8のBOM付きで生成します。

CSV数式として解釈される可能性がある先頭文字を含む値は、
表計算ソフトで数式として実行されにくいよう無害化します。

● メタデータ

画像の保存時には、現在の見た目をCanvasから新しい画像として書き出します。

このため、元画像に含まれていた次のようなメタデータは、
原則として保存画像へ引き継がれません。

- EXIF情報
- GPS位置情報
- 撮影日時
- 撮影機種
- カメラ設定
- 元画像に含まれていたサムネイル

注意:
「元画像のメタデータを引き継がない」ことを目的とした設計です。

ブラウザや画像形式によって、新しい画像の生成に必要な情報が
付加される可能性まで含めて、全種類のメタデータが存在しないことを
保証するものではありません。

庁外公開等の重要な用途では、保存後の画像について別の確認手段でも
メタデータを確認してください。


■ 7. セキュリティとプライバシー


本ツールの画像処理は、Microsoft Edgeのブラウザ内で行います。

- 画像をサーバーへアップロードしません。
- 画像を外部サービスへ送信しません。
- 外部APIへ画像を送信しません。
- クラウドへ自動保存しません。
- 画像データをWeb StorageやIndexedDBへ保存しません。
- 処理後の画像またはZIPは、利用者の操作により端末へダウンロードします。

ただし、ダウンロードしたファイル、ブラウザキャッシュ、OSの一時領域、
クリップボード等の取扱いは、端末およびブラウザの設定に従います。

個人情報または機密情報を含む画像は、所属組織の情報セキュリティポリシーと
データ取扱規程に従って使用してください。


■ 8. アクセシビリティと操作性


本ツールでは、次の操作性対応を行っています。

- キーボードフォーカス表示
- タブのARIA属性
- 左右矢印キーによるタブ切替
- HomeキーおよびEndキーによるタブ移動
- ダイアログのフォーカス制御
- Escapeキーによる比較ダイアログ終了
- OSの視覚効果を減らす設定への対応
- 目的別の折りたたみメニュー
- 画像直下のトリミング確定バー
- 状態表示のライブ通知


■ 9. 既知の制約


- HEIC、HEIF、GIF、BMP、TIFF、SVG、RAW画像には対応していません。
- アニメーション画像には対応していません。
- 一括処理では個別のトリミング、モザイク、黒塗り、注釈はできません。
- ZIPは無圧縮方式です。
- 一括処理の中止は、現在処理中の画像が終了した後に行われます。
- 目標容量を必ず達成できるとは限りません。
- 証明写真の物理寸法またはDPIを保証するものではありません。
- 操作履歴はページを閉じると失われます。
- 保存画像には編集可能なレイヤー情報は残りません。
- モザイクは元画像を基に生成します。
- モザイク処理は対象情報の完全な秘匿を保証するものではありません。
- 画像の内容や端末性能によっては、上限以内でも処理に時間がかかります。
- ZIP生成時は、画像データをブラウザのメモリ上へ展開します。
- ブラウザが選択した出力形式に対応していない場合は保存できません。

HTML内のmeta要素に加え、IISのHTTPレスポンスヘッダーでも
必要なセキュリティ設定を行ってください。

- X-Content-Type-Options: nosniff
- Referrer-Policy: no-referrer
- Content-Security-Policy
- frame-ancestors 'none'
- X-Frame-Options: DENY
- Permissions-Policy

本ツールのCSSおよびJavaScriptは、同一サーバー上の外部ファイルへ

  default-src 'self';
  script-src 'self';
  style-src 'self';
  img-src 'self' blob: data:;
  connect-src 'none';
  object-src 'none';
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';

IIS設定および庁内環境に合わせて調整してください。

■ 14. 更新履歴


● 操作履歴

「1つ戻す」と「やり直す」は、加工レイヤーの状態または画像本体の状態を
ブラウザのメモリ内へ保持して実現します。

画像本体を含む履歴の保持上限:
- 5,000,000画素以下: 最大8件
- 5,000,000画素超～10,000,000画素以下: 最大4件
- 10,000,000画素超～20,000,000画素以下: 最大2件
- 20,000,000画素超: 最大1件

レイヤーのみの履歴を含む全履歴:
- 最大40件

画像本体を含む履歴の例:
- トリミング
- リサイズ
- 回転
- 反転
- 読込み時の状態へ戻す

レイヤーのみの履歴の例:
- 加工レイヤーの追加
- 移動
- サイズ変更
- 順序変更
- 表示・非表示
- 設定変更
- 削除

トリミング確定前の枠は一時的な操作情報として扱い、
操作履歴には保存しません。

ページを閉じると操作履歴は失われます。
