お役立ちアプリBOX / 文章差分チェッカー  v1.4.0
======================================

本ツール自体の機能版数は、AppBox全体および共通assetsの版数とは別に管理します。
AppBox全体のリリース履歴はappbox\README.md / CHANGELOG.mdを参照してください。
共通assetsの仕様・版数はappbox\assets\README.txtを参照してください。


■ 1. 概要


本ツールは、新旧2つの文章をブラウザ上で比較し、追加、削除、
一致箇所を色分けして表示するWebアプリです。

URL、通知文、条例・規則、要綱、議案、広報原稿等の変更確認に
利用できます。

入力内容と比較処理はブラウザ内で完結します。
共有コード上、入力内容を外部API、外部クラウド、データベース等へ
送信または保存する処理はありません。


■ 2. 動作環境


サーバー:
- Windows Server
- IIS

クライアント:
- Microsoft Edge

利用する主なブラウザ機能:
- JavaScript
- DOM API
- Clipboard API
- DocumentFragment
- requestAnimationFrame
- TypedArray
- window.print
- CSS Media Queries
- CSS印刷スタイル

PHP、データベース、サーバー側プログラムおよび外部ライブラリは
使用しません。

本番配置前に、庁内で実際に使用するMicrosoft Edgeのバージョンで
動作確認してください。


■ 3. 構成ファイル


本ツールは次の4ファイルで構成します。

- index.html
- help.html
- textdiff.css
- textdiff.js

全て同じフォルダーへ配置してください。

配置例:

  textdiff/
    index.html
    help.html
    textdiff.css
    textdiff.js

index.htmlでは、次のCSSファイルを読み込みます。

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-components.css
- textdiff.css?v=1.4.0

help.htmlでは、次のCSSファイルを読み込みます。
本体のtextdiff.cssには依存しません。

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-help.css

重要:

キャッシュ更新用の「?v=」は管理単位に合わせます。
共通アセット（..\..\assets\）は共通assetsのバージョン、
textdiff.cssとtextdiff.jsは本ツールの機能版数を使用します。
本ツールはv1.4.0のため、専用CSS・JavaScriptは「?v=1.4.0」です。
共通assetsはv1.4.1とし、その参照は「?v=1.4.1」に統一します。


「../../assets/」はお役立ちアプリBOX共通のアセットです。
appbox\assets\を同時に配置しないと表示が崩れます。
本ツールだけを単独で切り出して配置することはできません。
詳細はappbox\assets\README.txtを参照してください。

共通CSSは必ずtextdiff.cssより前に読み込みます。
共通CSSはCSSカスケードレイヤー（@layer appbox）を使用しており、
レイヤーに属さないtextdiff.cssが常に優先されます。
そのため共通CSSを追加しても既存画面の見た目は変わりません。

index.htmlでは、次のJavaScriptファイルを読み込みます。

- textdiff.js?v=1.4.0

AppBoxの共通アセットを更新する場合は共通アセット参照の「?v=」を
共通assetsのバージョンへ更新します。本ツールだけを更新する場合は、
textdiff.cssとtextdiff.jsの「?v=」だけを本ツールの機能版数へ更新します。
AppBox全体のバージョンだけが変わった場合は、どちらの「?v=」も変更しません。

README.txtは管理者・保守担当者向け資料です。
公開ディレクトリへの配置は必須ではありません。
一般利用者向けのリンク先にはhelp.htmlを使用し、
README.txtへの直接リンクは画面へ表示しません。


■ 4. 配置・初期設定


1. IISの公開フォルダー配下へ、本ツール用フォルダーを作成します。

   例:
   C:\inetpub\wwwroot\appbox\apps\textdiff\

2. 次の4ファイルを配置します。

   - index.html
   - help.html
   - textdiff.css
   - textdiff.js

3. ブラウザから次のようなURLでアクセスします。

   http://<IISサーバー>/appbox/apps/textdiff/

4. IISの「静的コンテンツ」を有効にしてください。


■ 5. 主な機能と仕様


● 主な機能

- 新旧2つの文章を比較
- 左に旧・古い文章、右に新・新しい文章を表示
- 行内文字単位比較（推奨）
- 全文文字単位比較
- 行単位比較
- 比較単位を一覧できるラジオボタン
- 行単位で変更ブロックを検出し、対応行の内部を文字単位で比較
- 同数の変更行は同じ位置同士の対応を優先
- 行数が異なる変更ブロックは、行順と類似度により対応
- 対応しない行は、行全体の追加または削除として表示
- 追加箇所の強調表示
- 削除箇所の強調表示
- 差分の統合表示
- 追加、削除、一致、差分箇所の件数表示
- 一致率の概算表示
- 「前の差分」「次の差分」による差分箇所の移動
- Alt + ←およびAlt + →による差分箇所の移動
- 空白、全角空白、タブ、改行等の不可視文字表示
- 印刷および印刷用レイアウト
- 左右文章の入替え
- サンプル文章による試用
- Word向けの書式付きコピーと比較レポートのコピー
- 連続する空白・タブの正規化
- 全角英数字の正規化
- 連続する改行の正規化
- 新旧結果のおおよその位置でのスクロール連動
- 比較ルール変更時の自動再比較
- 入力・比較単位変更後の古い結果の無効化
- 長文比較時の処理上限
- Ctrl + EnterまたはCommand + Enterによる比較
- 比較完了時の結果見出しへのフォーカス移動
- ステータスの読み上げ対応
- レスポンシブ表示
- 利用者向けヘルプ画面
- ヘルプを新しいタブで表示

● 基本的な使い方

1. 左側の「旧・古い文章」へ古い文章を入力または貼り付けます。
2. 右側の「新・新しい文章」へ新しい文章を入力または貼り付けます。
3. 「比較単位」で次のいずれかを選択します。
   - 行内文字単位（推奨）
   - 全文文字単位
   - 行単位
4. 「差分を比較」を押します。
5. 必要に応じて、ボタン下部の「詳細カスタマイズ」を変更します。
   一度比較した後は、変更内容が比較結果へ自動で反映されます。
6. 比較結果、件数、一致率および差分箇所数を確認します。
7. 必要に応じて「前の差分」「次の差分」で差分箇所を移動します。
8. Wordへ貼り付ける場合は、統合表示の「Word向けにコピー」を押し、
   Wordで「元の書式を保持」を選択します。比較条件や集計も必要な場合は
   「比較レポートをコピー」、紙で確認する場合は「印刷」を押します。

入力欄では、次のショートカットでも比較できます。

- Ctrl + Enter
- Command + Enter

通常の文書比較では、「行内文字単位（推奨）」を使用してください。
文章全体に対する最短差分を確認したい場合は「全文文字単位」、
行全体の追加・削除だけを確認したい場合は「行単位」を使用してください。

● 新旧の入力方向

画面では次の方向で入力します。

- 左: 旧・古い文章
- 右: 新・新しい文章

追加とは、新しい文章に加わった文字または行を指します。
削除とは、古い文章からなくなった文字または行を指します。

「左右を入れ替え」を押すと、新旧の入力内容を交換します。
入替え後は、再度「差分を比較」を押してください。

● 行内文字単位比較（推奨）

行内文字単位比較は、最初に行単位で新旧文章を比較し、
変更された行の対応関係を決定した後、対応した行の内部だけを
Unicodeコードポイント単位で比較する方式です。

通常の文書比較では、この方式を推奨します。

主な処理:

1. 新旧文章の改行コードをLFへ統一
2. 選択された正規化を実行
3. 文章を行へ分割
4. 行単位のMyers法で一致行と変更ブロックを抽出
5. 変更ブロック内の旧行と新行を対応付け
6. 対応した行の内部だけを文字単位のMyers法で比較
7. 対応しなかった旧行を行全体の削除として処理
8. 対応しなかった新行を行全体の追加として処理
9. 同じ種類の差分を連結
10. 連続する追加・削除を差分箇所としてグループ化
11. 安全なDOM APIで結果を描画

変更ブロック内で削除行数と追加行数が同じ場合は、
同じ位置にある旧行と新行の対応を優先します。

削除行数と追加行数が異なる場合は、行の順序を維持しながら、
文字の共通度、共通する先頭・末尾、行の長さおよび行位置を
利用して対応候補を決定します。

対応行の内部はMyers法で比較します。
このため、文字の移動は単純な位置ごとの置換ではなく、
削除と追加として判定される場合があります。

行をまたいだ差分位置のずれは抑制できますが、行内に同じ文字が
繰り返し存在する場合は、人が想定する変更位置と異なる位置が
選択されることがあります。

● 全文文字単位比較

文章全体をUnicodeコードポイント単位に分割し、改行を含む
1つの文字列として比較します。

共通する先頭部分と末尾部分を先に確定し、その間の中央部分を
Myers法で比較します。中央部分の長さが同じ場合もMyers法を使用します。

表示の意味:

- 追加: 新しい文章に追加された文字
- 削除: 古い文章から削除された文字
- 一致: 新旧で一致した文字

改行を越えて最短差分を探索するため、繰り返し文字や同じ文字列が
複数行に存在する文章では、人が想定する行とは別の行に差分位置が
表示される場合があります。

行をまたいだ対応を避けたい場合は、
「行内文字単位（推奨）」を使用してください。

Unicodeコードポイント単位の比較であるため、結合文字や複数の
コードポイントで構成される絵文字は、見た目上の1文字が複数の
比較要素として扱われる場合があります。

● 行単位比較

改行で区切った各行を単位として比較します。

次の用途に適しています。

- 条文の追加・削除
- 段落単位の変更
- 表形式テキストの行変更
- ログや一覧の比較

行内の一部だけが異なる場合でも、その行全体を削除および追加として
扱います。行内の細かな変更箇所を確認する場合は、
「行内文字単位（推奨）」を使用してください。

表示の意味:

- 追加: 新しい文章に追加された行
- 削除: 古い文章から削除された行
- 一致: 新旧で一致した行

● 詳細カスタマイズ

通常は変更せず、そのまま比較できます。
設定は「比較ルール」と「表示・操作」に分かれています。

比較ルール:

1. 連続する空白・タブを1つの半角空白として比較

   次の文字が連続している場合に、1つの半角空白へ変換します。

   - 半角スペース
   - タブ
   - 全角スペース

   改行はこのオプションでは変更しません。

2. 全角英数字を半角として比較

   次の文字の全角・半角の違いを同一視します。

   - 英大文字
   - 英小文字
   - 数字

   例:

     ＡＢＣ１２３
     ABC123

   上記を同じ文字列として比較します。

   このオプションでは、丸数字、括弧付き文字、半角カナ、
   ダッシュ、ハイフン、マイナス、長音記号等は変換しません。

3. 連続する改行を1つの改行として比較

   2つ以上連続する改行を1つの改行へ変換します。
   複数の空行数を差分として扱いたくない場合に使用します。

表示・操作:

4. 空白・タブ・改行などの不可視文字を表示

   比較結果上で、見えにくい文字を次の記号で表示します。

   - 半角スペース: ·
   - 全角スペース: □
   - タブ: →
   - 改行: ↵
   - 改行しない空白: ⍽
   - ゼロ幅空白: [ZWSP]

   このオプションは比較結果の見た目だけを変更します。
   比較内容、追加・削除・一致の件数および一致率には影響しません。

   比較後にON・OFFを切り替えることができ、再比較は不要です。

5. 新旧の比較結果をおおよその位置で連動してスクロール

   左右の比較結果をスクロール率に応じて連動させます。

   追加・削除量が左右で大きく異なる場合、対応箇所が完全には
   揃わないことがあります。これは簡易的な比率同期です。

   正確な位置を確認する場合は、差分移動機能または統合表示も
   併用してください。

● 正規化時の表示

正規化オプションを有効にした場合、比較結果には原文ではなく
正規化後の文章を表示します。

例えば、連続する空白を正規化した場合は次のようになります。

  原文: A　　B
  表示: A B

正規化は比較時だけ行い、入力欄の原文自体は変更しません。

正式文書の最終確認では、正規化結果だけでなく入力した原文も
併せて確認してください。

● 比較結果

比較結果には次を表示します。

- 追加件数
- 削除件数
- 一致件数
- 差分箇所数
- 一致率
- 左側に旧・古い文章
- 右側に新・新しい文章
- 統合表示

文字単位では件数の単位を「文字」、行単位では「行」として表示します。

連続する追加・削除のまとまりを1つの差分箇所として数えます。
一致する文字または行を挟むと、別の差分箇所として数えます。

一致率は、次の考え方による概算値です。

  一致数 ÷ 新旧のうち長い方の要素数 × 100

正規化後に新旧の比較対象がともに空になった場合は、一致率を
100%として表示します。

一致率は内容の意味的な類似度を示すものではありません。

● 差分箇所の移動

差分がある場合は、「前の差分」と「次の差分」を使用して、
差分箇所を順番に確認できます。

現在位置は、次の形式で表示します。

  差分 2 / 5

これは全5か所のうち、2か所目を選択していることを示します。

選択中の差分は黄色の枠で強調されます。
差分移動時は、左側の旧文章を優先して比較結果欄内をスクロールし、
旧側に対象要素がない場合は右側の新文章へ移動します。

最後の差分で「次の差分」を押すと最初へ戻り、
最初の差分で「前の差分」を押すと最後へ移動します。

次のキーボード操作にも対応します。

- Alt + ←: 前の差分
- Alt + →: 次の差分

● コピー機能

【Word向けにコピー】

統合表示の本文を、次の書式でコピーします。

- 追加: 青文字
- 削除: 赤文字＋取り消し線
- 変更なし: 黒文字

比較条件、集計、見出し、凡例、差分の説明ラベルは含めません。
背景色や現在位置の黄色い枠も含めません。
不可視文字表示がONでも、表示用の記号ではなく元の空白・タブ・改行を
渡します。入力本文に実際に含まれる「追加箇所」等の文字は残します。
正規化がONの場合は、比較に使用した正規化後の文章をコピーします。
差分がない場合も統合表示とコピー機能を利用できます。

Wordでは、貼り付け時に「元の書式を保持」を選択してください。
これは文字色と取り消し線を付けた文章であり、Wordの「変更履歴」を
作成する機能ではありません。

HTML形式とテキスト形式を同時にクリップボードへ渡します。
「テキストのみ保持」で貼り付けた場合や、書式非対応のアプリでは、
色と取り消し線は反映されず、追加・削除の両方の本文が残ります。
貼り付け先のアプリや設定により、書式や空白の見え方が異なるため、
利用するWordと文書で貼り付け結果を確認してください。

【自動コピーできない場合】

HTTPS等の安全なコンテキストでは、対応するClipboard APIを使用します。
HTTP配置、API非対応、権限拒否等の場合は、従来型のコピー機能で
HTML形式とテキスト形式のコピーを試行します。
書式付きコピーが確認できなければ、成功とは表示せず、コピー用表示を
開きます。統合表示の「コピー用表示」ボタンからも開けます。

1. 「本文をすべて選択」を押します（開いた直後は本文が選択されています）。
2. Ctrl+C（Macは⌘C）または右クリックでコピーします。
3. Wordで「元の書式を保持」を選択して貼り付けます。

コピー用表示には、説明ラベルや表示用の不可視文字記号を含めません。
「閉じる」またはEscで戻ります。入力や比較条件を変更した場合は、
古い本文をコピーしないよう結果とコピー用表示を無効化します。

【比較レポートをコピー】

従来の「差分結果をコピー」を「比較レポートをコピー」に改称しました。
比較条件、集計、新旧の文章、統合表示を含むテキスト形式です。
文字単位の比較では【削除:…】【追加:…】、行単位では行頭の- / +などで
差分を示します。文字色と取り消し線は付きません。


● 印刷機能

「印刷」を押すと、ブラウザの印刷画面を開きます。

印刷時は、入力欄、操作ボタン、差分移動ボタンおよびフッターを
非表示にし、比較結果を印刷向けレイアウトで表示します。

印刷対象:

- アプリ名
- 比較条件
- 正規化後表示の注意
- 追加、削除、一致、差分箇所、一致率
- 凡例
- 旧・新の比較結果
- 統合表示

印刷結果は、Microsoft Edge、プリンタードライバー、用紙サイズ、
倍率および背景グラフィックの設定等により異なります。

差分の背景色を印刷する場合は、Microsoft Edgeの印刷設定で
「背景のグラフィックス」を有効にする必要がある場合があります。

● 入力・設定変更後の結果

比較後に次を変更すると、表示中の結果を無効化し、コピーおよび
印刷ボタンを使用できない状態にします。

- 新しい文章
- 古い文章
- 比較単位

変更後は「差分を比較」を再度押してください。

一度比較した後に次の比較ルールを変更すると、自動的に再比較します。

- 空白・タブの正規化
- 全角英数字の正規化
- 連続改行の正規化

自動再比較で文字数・処理上限のエラーになっても、入力や比較単位を変更していなければ、
比較ルールを変更した時点で再試行します。

次の設定は比較内容そのものを変更しないため、結果へ即時に反映します。

- 不可視文字表示のON・OFF
- スクロール連動のON・OFF

不可視文字表示を変更した場合は、現在の比較結果をその設定で
再描画します。

● 処理上限

長文または差分が非常に大きい文章によるブラウザ停止を抑えるため、
次の上限を設けています。

- 行内文字単位比較: 左右合計30,000文字
- 全文文字単位比較: 左右合計30,000文字
- 行単位比較: 左右合計10,000行
- Myers法の探索深度: 1,200
- 比較時間の目安: 1,500ミリ秒
- 描画する差分区間: 20,000区間
- 行対応を行う変更ブロック: 旧側・新側とも最大80行
- 行対応表の大きさ: 最大1,600組

変更ブロックが行対応の上限を超えた場合でも、比較全体を必ず中止する
わけではありません。そのブロックの行内対応を省略し、旧行全体の削除と
新行全体の追加として表示します。

その他の上限へ達した場合は比較を中止し、文章の分割または行単位比較を
案内します。

比較時間はメインスレッド上で一定回数ごとに確認しています。
1,500ミリ秒で厳密に処理が停止することを保証するものではありません。

● 長文比較の注意

本ツールの差分計算はブラウザのメインスレッド上で実行します。
処理上限により長時間停止の危険を低減していますが、PC性能、文章内容、
差分量等によっては、一時的に画面操作への反応が遅くなる場合があります。

長文を比較する場合は、次の方法を推奨します。

- 通常は「行内文字単位（推奨）」を使用する
- 章、条、項等の単位に分割する
- 行全体の変更だけを確認する場合は「行単位」を使用する
- 改行を越えた最短差分が必要な場合だけ「全文文字単位」を使用する
- 他の作業内容を保存してから実行する

● 差分アルゴリズム

本ツールには、次の3種類の比較方式があります。

1. 行内文字単位（推奨）
2. 全文文字単位
3. 行単位

共通処理:

1. 新旧文章の改行コードをLFへ統一
2. 選択された正規化を実行
3. 比較方式に応じて文章を行またはUnicodeコードポイントへ分割
4. 共通する先頭部分を固定
5. 共通する末尾部分を固定
6. 中央部分をMyers法で比較
7. 同じ種類の差分を連結
8. 連続する追加・削除を1つの差分箇所としてグループ化
9. document.createElement、textContent等の安全なDOM APIで描画

行内文字単位では、行単位の差分結果から変更ブロックを抽出し、
ブロック内の旧行と新行を対応付けます。

削除行数と追加行数が同じ変更ブロックでは、
同じ位置の旧行と新行を対応させます。

行数が異なる変更ブロックでは、行の順序を維持した動的計画法を使用し、
行の文字構成、共通する先頭・末尾、長さおよび相対位置から算出した
類似度により対応行を決定します。

類似度が基準未満の行は無理に対応させず、行全体の追加または削除として
扱います。また、大きな変更ブロックは誤対応と処理時間増大を避けるため、
行内対応を行わず、行全体の追加・削除として扱う場合があります。

対応した行の本文は、Unicodeコードポイント単位のMyers法で比較します。
行末改行は本文と分けて比較し、新旧双方に存在する場合は一致、
一方だけに存在する場合は追加または削除として扱います。

Myers法は最短の編集経路を探索しますが、意味的な文章比較や、
人が意図した変更位置の推定は行いません。

● 操作ショートカット

- Command + Enter: 差分を比較

比較結果表示後に使用:

- Alt + →: 次の差分

- XMLHttpRequest
- WebSocket
- 外部API
- 外部CDN
- データベース
- Cookieへの保存
- localStorageへの保存
- sessionStorageへの保存

- 色だけでなく、凡例、取り消し線および文字装飾で
  追加・削除を示します。

■ 9. 既知の制約


- 意味的な文章比較ではなく、文字または行の機械的な比較です。
- 同義語、表記の意味、文法上の同一性は判定しません。
- 正規化ON時は正規化後の文章を結果へ表示します。
- 行単位比較では行内の細かな変更箇所を表示しません。
- 行内文字単位は、行をまたいだ差分位置のずれを抑制しますが、
  人が意図した行対応を常に保証するものではありません。
- 削除行数と追加行数が同じ変更ブロックでは、位置対応を優先するため、
  行の移動を行内変更として表示する場合があります。
- 行数が異なる変更ブロックでは、類似度と順序による推定を行うため、
  内容が似た行が多数ある場合は、想定と異なる行が対応する場合があります。
- 類似度が低い行は、行内差分ではなく行全体の削除・追加として表示します。
- 大きな変更ブロックでは、行内対応を省略して行全体の削除・追加として
  表示する場合があります。
- 対応行の内部に繰り返し文字がある場合は、人が想定する変更位置とは
  異なる差分が選択されることがあります。
- 全文文字単位では、同じ文字列が複数行に存在すると、
  差分位置が別の行へ移る場合があります。
- Unicodeコードポイント単位の比較であり、書記素クラスタ単位では
  ないため、結合文字や複合絵文字を分割して扱う場合があります。
- スクロール連動は比率同期のため、対応位置が完全には揃わない場合があります。
- 比較処理中は一時的に画面操作への反応が遅くなる場合があります。
- コピー機能はブラウザ設定により利用できない場合があります。
- 厳密なUnified Diffファイルの生成機能はありません。
- 行番号表示機能はありません。
- 結果のファイル保存機能はありません。
- 入力内容および比較結果の履歴保存機能はありません。
- 差分箇所数は連続する追加・削除のまとまりを単位とする概算です。
- 印刷結果はブラウザ、プリンターおよび印刷設定に依存します。
- HTTP環境で使用するフォールバックコピーは旧方式のAPIに依存し、
  ブラウザの設定によって利用できない場合があります。


■ 10. 運用・保守


HTML内のCache-Control等のmeta要素は、全てのキャッシュ制御を
保証するものではありません。

必要に応じてIIS側のHTTPレスポンスヘッダーで、次を設定してください。

- Cache-Control: no-store
- Pragma: no-cache
- X-Content-Type-Options: nosniff
- Referrer-Policy: no-referrer
- X-Frame-Options: DENY
- Content-Security-Policy
- Permissions-Policy

本ツールは外部リソースを使用しないため、同一オリジン中心の
Content-Security-Policyを設定できます。

CSP設定例は、実際のIISおよびMicrosoft Edge環境で検証してから
適用してください。
