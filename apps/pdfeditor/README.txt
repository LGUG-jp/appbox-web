共創アプリBOX / PDFかんたん編集  v1.13.0
===========================================

現在の共通assets版: v2.3.0。Issue #160の作業ファイル（.abpdf）の保存・読込みを追加し、アプリ固有版をv1.13.0へ更新しました（未リリース）。
過去の変更履歴に記載された共通assets版は当時の記録です。

本ツール自体の機能版数は、AppBox全体および共通assetsの版数とは別に管理します。
AppBox全体のリリース履歴はappbox\README.md / CHANGELOG.mdを参照してください。
共通assetsの仕様・版数はappbox\assets\README.txtを参照してください。


■ 1. 概要


● 概要

「PDFかんたん編集」は、PDFの軽微な編集をブラウザ内で行う
庁内向けの静的Webアプリです。

主な機能:

- 複数PDFの追加・結合
- ページのドラッグ＆ドロップによる並べ替え
- 選択ページを「前へ」「後ろへ」移動
- ページの左回転・右回転
- ページ削除
- ページ番号の一括付与（開始ページ・開始番号・6か所の表示位置・文字サイズ、適用前プレビュー）
- 透かしの一括付与（プリセット／自由入力、色・不透明度・文字サイズ・角度、全ページ／選択ページ、適用前プレビュー）
- 一覧と個別編集の切替、ページ複数選択・一括操作・選択ページ抽出
- 一覧のサムネイルサイズ切替（小・中・大）
- 個別編集時のページ一覧の表示／折りたたみ
- PNG・JPEG画像のファイル選択／Ctrl＋V挿入・移動・比率固定リサイズ
- スタンプ（四角・丸、mm指定のサイズ、3行までの文字、{date}による配置日の西暦・和暦表示、色・枠線・背景・両端揃え・区切り線、テンプレートのファイル保存・読込み）
- 初期画面でクリップボードのPDFファイルをCtrl＋Vで読込み（対応環境のみ）
- 日本語テキストの追加
- テキストの文字色、背景色、透明背景、フォント、文字サイズ、太字の設定
- フォント選択時のライブプレビュー
- 四角枠の追加
- 丸、矢印、線の追加
- ペン・マウスによる手書き注釈、線色／線幅、ストローク単位の消しゴム（指入力は明示的な切替）
- PDF本文の文字選択による蛍光マーカー（文字情報がないPDF・OCRには非対応）
- テキスト・矢印の白縁（初期状態で有効）
- 複数図形の選択・移動・削除・ページ間コピー＆ペースト
- 追加した図形・文字・画像・スタンプ・手書き・マーカーの最前面／最背面への移動
- 編集領域の四隅へ移動できる設定パネル
- 図形の移動・サイズ変更
- 四角・丸はShift／Ctrlで正方形・真円に固定。線・矢印はCtrlで水平／垂直に固定し、作成済み端点はShiftで元の角度を維持して伸縮
- Undo・Redo
- PDFを閉じてブラウザ内の作業状態を破棄
- 未保存の変更がある場合の閉じる・再読み込み・ブラウザ終了時の確認
- 編集済PDFの保存
- 作業ファイル（.abpdf）の保存・読込み（ページ構成を確定し、追加した図形・ページ番号・透かしを後から再編集）

既存PDF本文の文字列を直接書き換える機能はありません。

● 重要: マスキング用途で使用しないでください（データは見えます）

本ツールの四角・丸・テキスト・画像・手書きは、元の文字や画像の上へ表示を
重ねる機能です。

四角・丸・テキスト・画像・手書きを重ねても、下にある元の文字、画像およびデータは
PDF内に残ります。

次の用途には使用しないでください。

- 個人情報の削除または非表示
- 機密情報の削除または非表示
- 非公開情報の削除または非表示
- 文書の墨消し、黒塗り、マスキング
- 元データを復元不能にする処理

個人情報や機密情報を削除する場合は、正式な墨消し機能を備えた
承認済みのPDFソフトウェアを使用してください。


■ 2. 動作環境


主な対象:

- Microsoft Edgeの組織内でサポートされている現行版

必要なブラウザ機能:

- ES Modules
- PDF.js Worker
- Canvas
- HTMLDialogElement（showModal）
- Blob
- URL.createObjectURL
- File API
- Fetch API
- Streams API
- DecompressionStream
- TextEncoder
- Pointer Events
- Drag and Drop API
- crypto.randomUUIDまたは代替ID生成
- Optional Chaining
- CSS.escape

古いブラウザやInternet Explorerには対応しません。

● 構成ファイル

操作アイコンは ../../assets/appbox-icons.css と appbox-icons.svg に依存します。
共通assets v2.3.0を同時に配置し、SVGが image/svg+xml で返ることを確認してください。
ボタンの日本語ラベル・操作は維持し、図柄の正本は共通SVGで管理します。

準備用スクリプトを使用する構成では、必要に応じて次も含めます。

  prepare-vendor.ps1
  verify-offline.ps1

使用しているHTML、CSS、JavaScriptおよびvendorファイルは、
同じリリース版の組合せで配置してください。

共創アプリBOX共通のアセット:

index.htmlが読み込む共通ファイル:

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-collapse.js

appbox-collapse.jsは、アプリ導入部とマスキングの注意喚起を開閉するための
共通処理です。app.jsとは独立して動作します。
実際に隠すCSSと、空いた高さの再配分はapp.cssへ記述しています。
詳細は「■ 30. 画面表示」を参照してください。

help.htmlが読み込む共通ファイル:
本体のapp.cssには依存しません。

- ../../assets/appbox-tokens.css
- ../../assets/appbox-themes.css
- ../../assets/appbox-base.css
- ../../assets/appbox-chrome.css
- ../../assets/appbox-help.css
- ../../assets/appbox-help-theme.css

重要:
appbox\assets\を同時に配置しないと表示が崩れます。
本ツールだけを単独で切り出して配置することはできません。
詳細はappbox\assets\README.txtを参照してください。

共通CSSは必ずapp.cssより前に読み込みます。
共通CSSはCSSカスケードレイヤー（@layer appbox）を使用しており、
レイヤーに属さないapp.cssが常に優先されます。
そのため共通CSSを追加しても既存画面の見た目は変わりません。

本ツールのweb.configはstyle-srcを'self'に限定しています。
'unsafe-inline'を含めていないため、index.htmlとhelp.htmlには
インラインの<style>要素およびstyle属性を記述できません。
テーマの色は必ず共通CSSファイル経由で適用してください。

利用者向けの説明はhelp.htmlです。
README.txtは管理者・保守担当者向け資料であり、
一般利用者向けのリンク先には使用しません。

● CMapバンドル

一部の日本語PDF、CIDフォントを使用したPDF、縦書きPDF等を表示するため、
次のファイルを使用します。

  vendor/cmaps.bundle.json.gz

このファイルは、PDF.js用のテキストCMapをJSONオブジェクトへまとめ、
gzip形式で圧縮したローカルバンドルです。

アプリは必要なCMap名をPDF.jsから受け取り、バンドル内の同名データを
検索して返します。

CMap名には英数字、ピリオド、アンダースコアおよびハイフンだけを許可し、
想定外のパスや名前を指定できないよう制限しています。

次の場合はPDFの読込みに失敗します。

- cmaps.bundle.json.gzが配置されていない
- IISから取得できない
- gzip形式として展開できない
- JSONとして読み込めない
- 必要なCMapがバンドルに含まれていない
- CMapデータが空または不正である
- ブラウザがDecompressionStreamに対応していない

CMapバンドルの作成方法、作成元、対象ファイル、ライブラリ版および
ハッシュ値を運用資料へ記録してください。


■ 4. 配置・初期設定


● 初回準備

配布物にvendorフォルダーが含まれていない場合は、インターネットへ
接続できる準備用PCで必要なファイルを取得します。

準備用スクリプトを使用する構成では、例として次を実行します。

  powershell -ExecutionPolicy Bypass -File .\prepare-vendor.ps1

実行後、vendorフォルダーへ固定バージョンのライブラリとCMapバンドルを
配置します。

- pdf-lib 1.17.1
- pdfjs-dist 5.3.31
- PDF.js Worker 5.3.31
- OpenJPEG WASM / JavaScript fallback（PDF.js 5.3.31同梱資産）
- qcms WASM（PDF.js 5.3.31同梱資産）
- cmaps.bundle.json.gz

同時に、第三者ライセンス原文とSHA-256一覧を取得・作成する構成を
推奨します。

準備後は、次を実行して確認します。

  powershell -ExecutionPolicy Bypass -File .\verify-offline.ps1

確認対象:

- 必要なvendorファイルが存在する
- バージョンが想定どおりである
- SHA-256が記録値と一致する
- cmaps.bundle.json.gzが正しいgzip形式である
- CMapバンドルをJSONとして展開できる
- 実行時に外部URLを参照しない
- web.configのCSPが想定どおりである

準備用スクリプトの内容と取得先は、実運用前に管理者が確認してください。

● IIS配置例

共創アプリBOXの配置先が次の場合:

  C:\inetpub\wwwroot\appbox\

次のように配置します。

  C:\inetpub\wwwroot\appbox\apps\pdfeditor\
    index.html
    app.css
    app.js
    web.config
    LICENSE.txt
    README.txt
    THIRD_PARTY_LICENSES.txt
    vendor\
      pdf-lib.esm.js
      pdf.min.mjs
      pdf.worker.min.mjs
      cmaps.bundle.json.gz
      wasm\
        openjpeg.wasm
        openjpeg_nowasm_fallback.js
        qcms_bg.wasm
    licenses\
      各ライセンス原文

アクセス例:

  http://<IISサーバー>:<ポート>/pdfeditor/

IISでは、少なくとも次の静的ファイルを配信できる必要があります。

- .html
- .css
- .js
- .mjs
- .json
- .gz
- .wasm

cmaps.bundle.json.gzは、ブラウザ側でDecompressionStreamを使用して
展開します。

IISやリバースプロキシがこのファイルを自動的に再圧縮したり、
意図しないContent-Encodingを追加したりしないことを確認してください。

OpenJPEGとqcmsのWASMはvendor/wasm/から同一オリジンで読み込みます。
web.configでは.wasmをapplication/wasmとして配信します。OpenJPEGのWASM初期化に
失敗した場合は、同じvendor/wasm配下のJavaScriptフォールバックを使用します。


■ 5. 主な機能と仕様


● 処理方式

入力PDFは利用者のブラウザ内で読み込みます。

- PDF.jsでPDFを表示
- pdf-libで編集済PDFを作成
- ブラウザのCanvasでテキストを画像化
- Blob URLを使用して編集済PDFをダウンロード
- PDF.jsが必要とするCMapを同一オリジンの圧縮バンドルから取得
- gzip形式のCMapバンドルをブラウザ内で展開
- JPEG 2000 / JPXDecode画像を同一オリジンのOpenJPEG実行資産で復号
- PDF内のICCカラープロファイルを同一オリジンのqcms WASMで処理

アプリの共有コードには、入力PDFや図形をIISへアップロード・保存する
処理はありません。

また、共有コードには、入力PDFを外部API、外部クラウド、外部CDNへ
送信する処理はありません。

ただし、アプリ本体、PDF.js WorkerおよびCMapバンドル等の静的ファイルを
IISから取得するため、同一オリジンへの通常のHTTPアクセスは発生します。

web.configでは、Content-Security-Policyにより外部通信を制限します。
実際の運用時は、Microsoft Edgeの開発者ツール等で想定外の通信が
発生しないことを確認してください。

● PDF入力上限

ブラウザのメモリ不足や停止を抑えるため、次の上限を設定しています。

- 1ファイル: 100MB以下
- 読み込むPDFの合計: 200MB以下
- 総ページ数: 300ページ以下

複数PDFを同時選択する場合も、全ファイルの合計容量と総ページ数が
上限以内である必要があります。

これらは入力ファイル容量の上限です。
PDF.js、pdf-lib、Canvas、CMapおよび書き出し処理等により、
実際のメモリ使用量は入力ファイル容量より大きくなる場合があります。

利用端末の性能やPDFの内容によっては、上限以内でも処理が遅くなったり、
ブラウザのメモリが不足したりする場合があります。

● 基本操作

1. 画面中央の「PDFを選択」ボタンを押してPDFを選択します。ドロップ領域の余白をクリックしてもファイル選択画面は開きません。
2. 別のPDFを結合する場合は共通ヘッダーの「開く」を押します。
3. ページ一覧で対象ページを選択します（Ctrlで追加・解除、Shiftで範囲選択）。
4. 必要に応じてページの回転、並べ替え、削除を行います。
5. ページの「編集」を押して個別編集を開き、テキストや図形を配置します。
6. 必要に応じて図形の色、線幅、フォント等を変更します。
7. 共通ヘッダーの「保存」を押し、メニューから「PDFを保存（全ページ）」を選びます。
   続きを後で編集する場合は「作業ファイル（.abpdf）を保存」を選びます。
8. 作業を破棄する場合は共通ヘッダーの「閉じる」を押します。

● ページ操作

ページ選択:

- 一覧のサムネイルをクリック、Spaceで選択。Ctrl／Shiftやチェックボックスで複数選択
- チェックボックスの周囲40px（タッチ44px）もクリックでき、再度押すと最後の選択も解除
- 灰色の余白クリックで全選択を解除。0件選択では回転・移動・削除・選択保存を無効化
- 余白からの矩形ドラッグで交差するページを選択。Ctrl／Shiftで追加、上下端で自動スクロール
- Esc、ポインターキャンセル、画面離脱時は矩形選択前の状態へ戻す
- サムネイルへフォーカスしてEnter、または「編集」で個別編集へ移動
- 個別編集では、左側のサムネイルまたは上部の前ページ・次ページボタンを使用

ページ並べ替え:

- サムネイルをドラッグし、挿入位置を示す1本の線へドロップ
- 選択ページを「前へ移動」「後ろへ移動」の矢印アイコンで移動

ページ回転:

- 左回転アイコンで左へ90度回転
- 右回転アイコンで右へ90度回転

ページ削除:

- ごみ箱アイコン、または一覧にフォーカスしてDeleteで選択ページを確認なしで削除
- Undoで復元可能。Deleteを押し直すと、削除後に選択された次のページも削除できる
- 削除対象の先頭位置に残るページ（末尾なら直前）を選択し、削除件数・残りページ数・Undoの案内を画面に通知
- 一覧からDeleteした後は選択ページのサムネイルへフォーカスを戻し、矢印キー・Enterも続けて使用可能
- Deleteを押し続けても続けて別のページを削除しない
- 最後の1ページは削除できません
- 文書全体を閉じる場合は共通ヘッダーの「閉じる」を使用

ページの並べ替え、回転、削除は複数選択に対応し、Undo・Redoの対象です。
チェックボックスでも複数選択できます。「編集」で個別編集へ移動します。
「選択を保存」は選択ページのみ、「保存」メニューの「PDFを保存（全ページ）」は全ページを出力します。
抽出しても作業中のページは減りません。

「一覧の大きさ」でサムネイルを小・中・大に切り替えます。
大サイズのみ必要な解像度で再描画し、小・中では同じ描画結果を再利用します。
切替時は一覧で見ていた位置を維持します。ページ順や選択、履歴は変更しません。

図形の複数選択はShift＋クリックまたは余白から囲むドラッグを使います。
Ctrl＋C／Ctrl＋Vに加え、図形を右クリック（タッチ端末では長押し）して表示するメニューからコピー・貼り付けできます。
図形をコピーした後は、図形のないページでも余白を右クリックして貼り付けできます。タッチ端末では「選択」ツールで余白を長押ししてください。余白をドラッグすると従来どおり矩形選択になります。
アプリ内のコピーだけに対応し、閉じると破棄します。
重ね順は個別編集のツール列にある「最前面に移動」「最背面に移動」アイコン、または右クリック／長押しメニューから変更します。
対象は現在ページで追加した注釈同士です。複数選択は互いの順序を維持して一括移動し、
すでに端にある場合・選択なし・処理中は操作を無効にして余分な履歴を作りません。
画面と全体保存／選択保存は同じ順序を使用し、1回の操作を1回のUndo／Redoで戻せます。
元PDFの内容は注釈より下、透かしは追加した注釈より下、ページ番号は注釈より上を維持します。
蛍光マーカーはPDFの文字をドラッグして選択すると行ごとに付きます。
画像だけのページでは利用できません。
保存したPDFを開き直した図形は再選択・再編集できません。続きを編集する場合は作業ファイルを使います（「作業ファイル」の節を参照）。

四角・丸・線・矢印は配置後も同じツールを維持し、続けてドラッグして追加できます。
作図中は既存図形の上や近くからも開始できます。サイズ変更ハンドルは「選択」中だけ表示します。
移動・サイズ変更をするときは「選択」ボタンまたはEscで切り替えます。
四角・丸はShiftまたはCtrlを押しながらドラッグすると、縦横比を1:1に固定して正方形・真円として作成できます。
作成済みの四角・丸は、右下のサイズ変更ハンドルをShiftまたはCtrlを押しながらドラッグすると、現在の縦横比を保ったまま拡大・縮小できます。
細い図形などで最小サイズとページ境界が競合する場合は、縦横比を保ってページ内に収まるサイズを優先します。

● 手書き注釈

個別編集の「手書き」でペン／マウスのドラッグをストロークとして追加します。
線色・線幅は既存設定を共用し、筆圧がない環境でも固定線幅で描きます。
手ぶれ補正は「なし」（初期値）・弱・中・強を選べ、新しく描くストロークだけに適用します。
補正後の点を小さな手ぶれでは保持し、大きな移動では入力点から一定距離で追従させます。
追従距離は弱1.5pt・中3pt・強6pt。表示倍率に依存せず、強いほど追従の遅れ・角の丸まりが増えます。
ペンを離した位置で終端を確定し、補正済みの点列をプレビュー・履歴・PDF保存で共用します。
既存ストロークの再補正と消しゴムの軌跡補正は行いません。
指は標準で無視し、「指でも描く・消す」を有効にした場合のみ描画／消去します。
指入力の切替は設定パネルの色・線と同じ行に配置し、オフでもペン／マウスは利用できます。
手書き／消しゴム中はPDF上の指スクロール／ピンチを停止します。
「選択」（Esc）へ戻すと余白の指スクロール／ピンチが使えます。図形の上は移動です。
消しゴムは触れた手書きストローク全体を消し、他の図形や元PDFには影響しません。
1ドラッグを1履歴とし、Escape・ウィンドウのフォーカス喪失・ページ／倍率／画面変更では
未確定の描画／消去を破棄します。別ポインターの移動／終了イベントは混ぜません。
選択後の移動・色／線幅変更・コピー・削除に対応。「選択」ツール中のみTabで手書きへ移り、
Enter・矢印キーでも選択／移動できます。
Shift・Tabだけでは描画を取り消しません。指入力オフ時は最初の指操作で切替方法を案内します。
消しゴムの輪付きカーソルは、線の縁から8 CSS pxの消去判定の目安です。触れた1本全体が消えます。
筆圧による可変線幅、部分消去、手書きストロークのリサイズは対象外です。

ポイントは表示ページ座標（PDF point、左上原点）で保持し、倍率やDPIに依存しません。
Pointer EventsとPointer Captureを使用し、利用可能ならgetCoalescedEventsも取り込みます。
プレビュー更新はrequestAnimationFrameでまとめ、全図形をポインター移動ごとに再生成しません。
1本8192点、全ページ合計20万点を上限とし、0.25pt未満の移動は間引きます。
合計上限はコピーの貼り付けにも適用。Undo／Redoは既存の40履歴上限を使用します。
PDF出力は同梱pdf-libで丸い端点・接合のベクトル線として重ね、タップ1点は円で出力します。
保存して開き直した手書きは元PDFの一部であり、手書き消しゴム・再編集の対象ではありません。
実端末の筆圧／パームリジェクション品質は保証しません。

● 画像の挿入

個別編集の「画像を挿入」からPNG・JPEGを1枚選び、ページ中央へ配置します。
個別編集画面のCtrl＋Vでも、クリップボードのPNG・JPEG画像を1枚ずつ挿入できます。
ブラウザがpasteイベントへ画像ファイルを渡す場合に対応し、URL／HTMLのみは非対応です。
画像ファイルが渡された場合は画像挿入を優先し、ファイルがない場合はアプリ内図形を貼り付けます。
テキスト入力中は通常の貼り付けを維持します。検証・上限・履歴・出力はファイル選択と共通です。
図形のCtrl＋C／メニューの「コピー」ではOSクリップボードへ案内文字列だけを入れ、古い画像を置き換えます。
図形本体やPDFデータはOSクリップボードへ渡さず、アプリ内のコピーを使います。
メニューのコピーはブラウザのcopyコマンド経由で同じ案内文字列へ置き換えます。
コピーが拒否された場合は成功扱いにせず、Ctrl＋Cでのコピーを案内します。
図形データの保持と右クリックメニューの貼り付けはアプリ内で完結します。
右下のハンドルで常に比率を保ってリサイズし、既存図形と同様に移動、削除、
ページ間コピー、Undo／Redo、全体保存・選択保存できます。
Tabで画像へフォーカスし、Enterで選択、矢印キーで移動（Shiftで10倍）、
右下ハンドルへTabで移り矢印キーで拡大・縮小できます。
画像は1ファイル20MB以下（変換後も含む）、各辺8192px以下・1600万画素以下。
画像データの合計はUndo／Redo履歴・アプリ内コピーを含め100MB以下です。
画像の形式・寸法をデコード前に検証し、ブラウザ内のCanvasで再エンコードします。
PNGの透過、JPEGのEXIF由来の表示方向を反映します。JPEGは再圧縮で画質が変わる場合があります。
同一画像は図形・履歴間で共有し、現在ページ・履歴・コピーの参照がなくなると
Blob URLと画像データを解放します。PDFを閉じた場合も全画像を解放します。
PDF保存時はPNG／JPEGを埋め込み、同一画像の複数配置は埋め込みを共用します。
保存後の画像は元PDFの内容となり、開き直して再選択・再編集はできません。

● 初期画面でのPDF貼り付け

初期画面にて、コピーしたPDFファイルをCtrl＋Vで読み込めます。
pasteイベントのclipboardDataにファイルがある場合のみ対応します。
ファイルが渡されない環境、PDF本文の文字・画面画像・URL・パス文字列には非対応です。
通常のファイル選択と同じ形式・容量・ページ数検証を適用し、複数PDFも結合できます。
クリップボード読取り権限やnavigator.clipboard.read()は使用しません。
個別編集中は画像ファイルのCtrl＋V挿入に対応し、ファイルがない場合は図形Ctrl＋Vとなります。
入力欄やテキスト編集での通常貼り付けは維持します。

● ページ番号の一括付与

1. ページ一覧の「ページ番号」を押します。ページの選択状態には依存しません。
2. 開始ページ（1〜文書のページ数）、開始番号（0〜999999）、
   表示位置（上／下 × 左／中央／右）、文字サイズ（6〜72pt、0.5pt刻み）、
   見開き配置、書式、余白を指定します。
   初期値は1ページ目から1、下中央、12pt、すべて同じ位置、「3」、余白は自動です。
3. 最初の対象ページのプレビューと、対象範囲・最終番号を確認します。
   プレビューは元PDFと追加予定の番号を表示し、追加済みの図形は省略します。
4. 「適用する」で開始ページから最後まで連番を追加します。
   表紙を除き2ページ目から1にする場合は、開始ページを2、開始番号を1にします。

- キャンセル・Escでは変更しません。適用・再設定はそれぞれ1回のUndo／Redoで取り消し・復元できます。
- 再設定はこの作業中に付与した番号をすべて置き換えます。開始ページより前の付与済み番号は取り除きます。
- 通常の図形とは別に管理し、図形の移動・コピー・削除では番号を変更しません。
- 黒色・透明背景・Arial（未インストール時は代替フォント）で配置します。
- 余白の「自動」は従来どおりの位置で、透明余白4ptを含む外枠まで10mm、内側の文字枠まで約11.4mmです。
  小さい用紙では縮めます。
  「mmで指定する」では上下・左右を3〜50mm（0.5mm刻み）で指定し、指定した余白は縮めません。
  番号が収まらないページがあると適用を中止します。
  付与後の回転で番号が収まらなくなる場合も、回転せず再設定を案内します。
- 見開き配置：「すべて同じ位置」「偶数の番号は左右を入れ替え」「偶数の番号は上下を入れ替え」。
  表示位置は奇数の番号に使い、偶数の番号では左右（または上下）を反転します。中央は、左右の
  入れ替えではそのまま、上下の入れ替えでは上・中央と下・中央が入れ替わります。
  奇数・偶数は印字する番号で判定し、回転後の表示ページ上で反転します。
  表紙など番号のないページがあると、印刷の表裏とずれる場合があります。
- 書式：「3」「3 / 10（番号 / 最終番号）」「- 3 -」。右側の番号は適用時の最後の番号で、
  並べ替え・削除・選択保存では計算し直しません（再設定すると計算し直します）。
- 「ページ番号を削除」で、追加した番号を全ページから外します。入力エラー中でも押せ、
  1回のUndo／Redoで取り消し・復元できます。元PDF内の番号は消しません。
- 回転済みページ・付与後の回転でも、表示上の指定位置へ正立した番号を配置します。
- 並べ替え・PDF追加・削除では自動採番し直しません。ページ構成を整えてから適用、または再設定してください。
- 保存時は既存テキストと同じくPNGとして埋め込みます。番号の検索・読み上げ・保存後の再編集はできません。
- 元PDF内の番号は消しません。保存PDFを開き直して再付与すると、元の番号に重なる場合があります。
- 装飾（枠や色）は未対応です。

● テキスト操作

テキストの追加:

1. 「テキスト」を選択します。
2. PDF上の配置したい位置をクリックします。
3. テキストを入力します。
4. 入力欄の外側をクリックして編集を終了します。

テキストの再編集:

- 選択ツールでテキストをダブルクリックします。タッチ端末ではダブルタップします。

テキストの移動:

- 選択ツールでテキストをドラッグします。

テキスト枠のサイズ変更:

- テキストを選択し、右下のハンドルをドラッグします。

空の新規テキスト:

- 何も入力せず編集を終了したテキスト枠は削除されます。
- 空テキスト作成前の不要なUndo履歴も取り除かれます。

● テキストの書式

設定できる項目:

- 文字色
- 背景色
- 背景の透明化
- フォント
- 文字サイズ
- 太字

選択できるフォント:

- BIZ UDゴシック
- BIZ UDPゴシック
- 游ゴシック
- 游ゴシック UI
- メイリオ
- MS ゴシック
- MS Pゴシック
- MS 明朝
- MS P明朝
- Segoe UI
- Arial
- Times New Roman

フォントメニューで選択肢へマウスポインターを重ねるか、
キーボードフォーカスを移動すると、選択中のテキストへ
フォントのライブプレビューを表示します。

選択を確定せずメニューから離れた場合は、元のフォントへ戻ります。

フォントファイルはアプリに同梱しません。
実行PCにインストールされているローカルフォントを使用します。

選択したフォントが端末にない場合は、設定済みの代替フォントを使用します。
そのため、選択名と実際に使用されるフォントが異なる場合があります。

● フォントメニューのキーボード操作

フォントボタンまたはフォントメニューでは、次の操作を利用できます。

- ArrowDown: メニューを開く、または次のフォントへ移動
- ArrowUp: メニューを開く、または前のフォントへ移動
- Home: 最初のフォントへ移動
- End: 最後のフォントへ移動
- Enter: 選択を確定
- Space: 選択を確定
- Escape: 選択を確定せず閉じる
- Tab: メニューを閉じて次の操作要素へ移動

メニューは表示領域に応じて下方向または上方向へ開きます。
メニューの高さはブラウザの表示領域内に収まるよう調整されます。

● 四角枠と矢印

四角枠:

- 「四角」を選択し、PDF上をドラッグして作成します
- 選択後に移動・サイズ変更できます
- 色と線の太さを設定できます

矢印:

- 「矢印」を選択し、始点から終点へドラッグして作成します
- 選択後に移動できます
- 色と線の太さを設定できます

四角枠と矢印はページ内容へ描画して保存します。
元PDFの文字や画像を削除する機能ではありません。

● Undo・Redo

次の操作はUndo・Redoの対象です。

- PDF追加
- ページ並べ替え
- ページ回転
- ページ削除
- 図形追加
- ページ番号の一括付与・再設定
- 図形移動
- 図形サイズ変更
- 図形削除
- 図形の書式変更
- 既存テキストの文字変更

履歴は最大40件です。

ショートカット:

- Ctrl + Z: 元に戻す
- Ctrl + Y: やり直す
- Ctrl + Shift + Z: やり直す
- Command + Z: 元に戻す
- Command + Y: やり直す
- Command + Shift + Z: やり直す

テキスト入力欄、入力要素または選択要素を操作中は、
アプリ全体のUndo・Redoショートカットを実行しません。

履歴復元中はUndo・Redoボタンを一時的に無効化し、
複数の復元処理が競合しないよう制御します。

● 図形の削除

図形を選択して、次のいずれかを実行します。

- 「削除」を押す
- Deleteキー
- Backspaceキー

テキスト入力中は、DeleteまたはBackspaceを押しても図形全体は
削除されません。

● PDFを閉じる

共通ヘッダーの「閉じる」を押すと、現在読み込んでいるPDF、ページ編集状態、
図形および履歴を破棄します。

未保存の編集内容は失われます。

未保存の変更がある場合だけ確認を表示し、PDFを読み込んだだけの場合や
「保存」メニューからPDF（全ページ）または作業ファイルを保存した後に変更していない場合は確認なしで閉じます。
ブラウザの再読み込み・タブ／ウィンドウ終了時も、未保存の変更がある場合は
ブラウザ標準の確認を表示します。

PDF（全ページ）と作業ファイルの保存は、ダウンロードを開始した時点で保存済みとして扱います。
保存先の選択を取り消した場合やダウンロードに失敗した場合もアプリでは
検出できないため、保存したファイルを確認してから閉じてください。

PDF.jsの描画を中断し、PDF.jsドキュメントを破棄し、
ブラウザ内で保持しているPDFデータを解放します。

ただし、ブラウザやOSによるメモリの実際の解放時期は
環境によって異なります。

● 処理中表示

PDFの読込み、追加、保存および終了処理中は、処理中表示を行います。

初回読込み時はPDF選択領域へ処理内容を表示します。

PDF編集画面が表示されている場合は、ページ一覧と編集領域を含む
編集画面全体へ処理中オーバーレイを表示します。

処理中は主な編集操作を無効化します。
処理内容の読み上げはステータス表示へ集約しています。

● プレビュー品質

編集画面のPDFプレビューは、表示サイズを維持したまま、原則として
高い内部解像度で描画します。

考慮する要素:

- 基準品質: 原則2倍
- デバイスピクセル比: 最大2.5
- Canvas最大辺: 8192px
- Canvas総画素数: 約2,000万画素

巨大ページや高倍率表示では、Canvasの上限内へ収めるため、
内部描画品質を自動的に下げる場合があります。

表示倍率が高く、CSS上の表示サイズ自体が非常に大きい場合でも、
内部描画倍率を1未満へ下げてCanvas上限内へ収めます。

「画面に合わせる」または「幅に合わせる」を選択している場合は、
ブラウザの表示サイズ変更後に現在ページを再描画します。

プレビュー品質の変更は編集画面だけに影響し、保存する元PDFページの
品質を意図的に低下させるものではありません。


表示倍率とスクロール:

表示倍率の指定:
- 画面に合わせる（初期値・幅と高さの両方に収める）
- 幅に合わせる（幅に合わせ、高さはスクロール）
- 25 / 50 / 75 / 100 / 125 / 150 / 200 / 250 / 300 パーセント

25パーセントは内部の下限（0.25倍）に合わせた段です。
この段が無いと、「画面に合わせる」で25パーセント付近まで縮んで
いる状態で「－」を押したときに、最小段まで逆に拡大してしまいます。

操作方法:
- ページ表示ツールバーの「－」「＋」ボタン
- 「表示」の選択肢から直接指定
- 表示領域上でCtrlキーを押しながらマウスホイール

「－」「＋」は上記の段階を1つずつ移動します。
「画面に合わせる」または「幅に合わせる」の状態から押した場合は、
直前の描画で実際に使われた倍率に最も近い段階から移動します。

Ctrlキーを押していない通常のホイール操作はスクロールとして動作し、
妨げません。Ctrl＋ホイールの拡大縮小は表示領域の上だけに限定して
いるため、それ以外の場所ではブラウザ標準の拡大縮小が働きます。

ブラウザ標準のCtrl＋プラス、Ctrl＋マイナス、Ctrl＋0は、
意図的に上書きしていません。画面全体を拡大したい場合に
使用できるようにするためです。

スクロール:
表示領域（.viewer-area）はoverflow:autoです。
倍率を上げてページが表示領域より大きくなると、縦横のスクロール
バーが表示されます。Shiftキーを押しながらのホイール操作で
横方向へスクロールできます。

注意:
- 倍率の内部上限は3倍です。「幅に合わせる」も3倍で打ち切ります。
- 表示領域をドラッグして紙面を掴んで動かす操作には対応していません。
  表示領域上のドラッグは、四角枠や矢印の作成に割り当てられています。
- 段階の数値はindex.htmlの<option>とapp.jsのzoomStepsで一致させて
  ください。一致していない値はselectへ代入できず無視されます。

● 元PDF機能の保持に関する制約

変更がない単一PDFは元PDFのバイト列をそのまま保存するため、元PDFの
内部構造もそのまま維持されます。

編集した場合はcopyPages()を優先して元ページをコピーしますが、
pdf-libで新しいPDFとして再構成するため、元PDFの高度な機能を完全に
保持することを保証するものではありません。

また、回転済みページへ図形を追加した場合は、embedPage()方式へ
フォールバックします。

そのため、編集後PDFでは次の機能や情報が維持されない、または正常に
動作しない場合があります。

- 電子署名と署名の有効性
- 入力フォーム
- しおり、アウトライン
- ページ内リンク、外部リンク
- 添付ファイル
- PDF注釈
- レイヤー
- JavaScript
- 動画、音声等のマルチメディア
- アクセシビリティタグ
- 文書構造情報
- メタデータ
- 特殊なページボックス
- 高度なインタラクティブ要素

電子署名済みPDFは編集対象にしないでください。

保存後PDFを正式文書として使用する場合は、必要な機能や情報が
維持されていることを必ず確認してください。

● メモリと削除ページ

ページを削除しても、UndoまたはRedoで復元できる間は、元PDFデータが
ブラウザメモリ内に残る場合があります。

現在のページ、Undo履歴およびRedo履歴のいずれからも参照されなくなった
元PDFデータは、PDF.jsドキュメントを破棄し、管理対象から削除します。

不要な元PDFの解放処理は直列化し、同じデータへ複数の破棄処理が
競合しないようにしています。

ただし、ブラウザやOSが実際にメモリを解放する時期は環境に依存します。

すべての元PDFデータと履歴を明示的に破棄する場合は、
共通ヘッダーの「閉じる」を使用してください。

● 画面表示

初期画面とヘッダーには、左上の淡いテーマ色から右下の白へ変化する
グラデーションを使用します。

編集画面はPDF用紙、テキスト背景色および図形色を識別しやすくするため、
白と中立的な灰色を中心とした表示へ切り替えます。

操作ツールバーは横スクロールさせず、画面幅に応じて折り返します。
一覧ではページ操作、個別編集では図形ツールを表示します。
PDF読込み後は、共通ヘッダーのロゴの右隣へ「開く」「閉じる」、
元に戻す・やり直す・保存メニューの順に左寄せで表示します。PDFを閉じると初期表示へ戻します。
共通assets v2.3.0のappbox-header--editorにより、横1024px以下または縦500px以下ではロゴをマークだけに切り替えます。
PDF読込み後のヘッダーは原則1段表示とし、横760px以下または縦500px以下では「ヘルプ」を隠します。横560px以下では「開く」「閉じる」「保存」の文字も省き、アイコン表示へ縮退します。「保存」のメニュー項目は文字で表示します。操作とポータルへの戻るリンクが重ならないよう、収まらない場合はヘッダーを折り返します。編集操作の縮小は固有CSS、ブランドの切替は共通CSSで調整します。
図形の設定パネルは色・線幅・フォント等の設定だけを表示し、見出し・余白のドラッグで四隅へ移動します。コピー・貼り付け・削除は右クリック／長押しメニューへ分離し、テキスト再編集はダブルクリック／ダブルタップで行います。
ボタン・設定欄・そのラベルからは移動を始めず、6px未満の手ぶれでは位置を変えません。
ヘッダーは見出しだけを表示し、見出し・余白のドラッグで位置を変更できます。
補助操作と図形ツールは統一SVGの小型アイコンとし、主要操作には文字を残します。
アイコンの説明は「PDFを閉じる」と同じブラウザ標準のツールチップへ統一しています。
マウスを重ねると表示し、表示までの待ち時間・位置・外観はブラウザに従います。
キーボード・読み上げ用のaria-labelも維持し、一覧開閉の説明は状態に合わせて更新します。
参考デザインに合わせ、紙はグレーの輪郭と折り返し、操作は太いカラーの塗りで表現します。
主要10操作のアイコンは24pxで表示し、回転アイコンの紙も大きくしています。
ページ移動は青緑、90度回転は青、Undo/Redoは紫、ページ削除は赤、
PDFを開くは黄色の開いたフォルダーと紙、閉じるは紙と赤い×、全体保存は緑です。
左右の移動・回転・履歴は対称な形とし、回転矢印は90度の円弧です。
無効な操作はグレー、ハイコントラスト表示ではシステム色を使います。
PDFの追加・終了は共通ヘッダーの「開く」「閉じる」から操作します。
一覧へPDFファイルをドラッグすると、線で示した先頭・ページ間・末尾に追加します。
複数PDFはファイル順・ページ順を維持して挿入し、元に戻す・やり直すも使えます。
個別編集では上部に現在ページと前後移動を表示し、ページ一覧の表示ボタンで
左側の一覧を開閉できます。画面幅700px以下では初期状態を折りたたみにしますが、
手動で開いたり閉じたりした状態を同じ作業中は優先します。
一覧の大きさ・開閉状態はブラウザ保存せず、PDFを閉じると初期状態へ戻します。

アプリ説明と注意喚起の表示:

PDFを読み込む前は、アプリ名・説明とマスキング用途に関する注意喚起を
表示します。PDFを正常に読み込むと、編集作業領域を最優先にするため、
次の表示を自動で隠します。

- アプリ名・説明
- マスキング用途に関する注意喚起
- 読込み前に使う「説明を閉じる」ボタン
- テキスト・フォントに関する常設案内
- 読込み件数などの状態帯（読み上げ用の状態通知は維持）
- アプリフッター

PDFを閉じると、これらは自動で再表示されます。
PDF読込み前に手動で案内を閉じたい場合は、ヘッダー右上の
「説明を閉じる」ボタンを使用できます。

閉じた状態は保存しません。localStorage、sessionStorage、Cookieを
使用しないため、ページを開き直すと必ず表示された状態に戻ります。

なお、四角・丸・テキスト・画像・手書きがある状態で保存すると、画面上の注意喚起が
隠れていても、マスキング用途に使用しない旨の確認メッセージを
必ず表示します（app.js内のconfirm）。

実装:

- ボタンの見た目と状態管理は共通の
  ..\..\assets\appbox-collapse.js と appbox-chrome.css です。
- 実際に隠す指定と高さの再配分はapp.cssの
  「折りたたみ（プレビューを広く使うため）」節です。
  共通CSSは@layer appbox内にあるため、.brandや
  .redaction-noticeのdisplay指定を打ち消せません。
  そのためこの指定はapp.css側に置いています。


■ 6. データの取扱い


● テキストの保存方式

テキストは保存時にブラウザのCanvasで高解像度PNGへ変換し、
PDFページへ画像として貼り付けます。
スタンプも配置時に同じくCanvasでPNGへ変換し、画像として貼り付けます。

利点:

- 日本語テキストを保存できる
- 太字、文字色、背景色、透明背景およびローカルフォントの見た目を反映できる
- 閲覧先PCに同じフォントがなくても、保存時の見た目を維持しやすい
- 元PDF本文全体を画像化せず、テキスト部分だけを画像化する

制約:

- 保存後のテキスト文字はテキスト検索できません
- 保存後のテキスト文字は文字選択できません
- 保存後のテキスト文字はコピーできません
- スクリーンリーダーで文字として読み上げられません
- PDFの注釈オブジェクトではなく、ページ内容へ画像として貼り付けます
- 大きく拡大するとベクター文字より粗く見える場合があります
- テキスト枠に収まらない文字は保存時に末尾が表示されない場合があります

保存前に、テキスト全文が枠内に表示されていることを確認してください。

● PDF保存

保存ファイルはブラウザからダウンロードします。

1つのPDFを開いただけで、ページ順、回転および図形を何も変更していない
場合は、pdf-libで再構築せず、読み込んだ元PDFのバイト列をそのまま
保存します。

これにより「何も編集していないのにファイルサイズが増える」現象を
抑えます。

編集、ページ削除、並べ替えまたは結合を行った場合は、原則として
copyPages()で元ページをコピーし、フォントや画像などの共有リソースの
重複を抑えます。

出力する各ページは、ページID単位の独立したPDFPageコピーとして扱います。
同じ元ページを複数回参照する構成でも、同一のPDFPageオブジェクトを
複数回出力へ追加しないようにしています。

回転済みページへ図形を追加したケースだけは、図形位置の互換性を優先し、
embedPage()方式へ自動的にフォールバックします。

保存ファイル名は、原則として出力先頭ページの元ファイル名を基準に
次の形式で作成します。

  元ファイル名_編集済.pdf

ファイル名にWindowsで使用できない文字や予約名がある場合は、
安全な名称へ置換します。

保存時に四角・丸・テキスト・画像・手書きがある場合は、マスキング用途に
使用しない旨の確認メッセージを表示します。


● 作業ファイル（.abpdf）

「保存」メニューの「作業ファイル（.abpdf）を保存」は、続きを編集するためのファイルを保存します。
配布用のファイルではありません。配布には「PDFを保存（全ページ）」でPDFを保存します。

保存時に確定するもの: ページの追加・削除・並べ替え・回転
再編集できるもの: テキスト・四角・丸・線・矢印・手書き・マーカー・画像・スタンプ・ページ番号・透かし

- 削除したページは作業ファイルに入らず、開き直しても戻りません
- Undo／Redoの履歴は保存しません。開いた直後は履歴が空です
- スタンプは配置時の画像のまま保持します（文字・日付の再展開はしません）
- 図形の重ね順を保持します

中身は無圧縮のZIPです。

  project.json … 形式・版、元のPDF名、ページごとの図形・ページ番号・透かしの設定
  base.pdf     … 保存時のページ構成で作り直したPDF（図形は含まない）
  images/…     … 図形として使っている挿入画像・スタンプだけ（PNG／JPEG）

base.pdfは通常のPDF保存と同じくcopyPages()でページをコピーし、
最終の回転角を設定します。図形は回転後の表示座標で保持しているため、
開き直しても同じ位置に戻ります。元PDFのしおり・添付ファイル・
文書のメタデータは持ち込みません。

copyPages()はページから参照されるものをすべてコピーするため、
残したページから削除したページへのリンク・フォーム・記事スレッド等の参照が
あると、削除したページの内容までコピーされます。コピー後に参照を消しても
データは残るため、作業ファイルではコピー前の元PDF（保存のためだけに読み込んだ複製）
に対して次を行います。

- 削除したページ、ページツリーに載っていないページ辞書、削除したページに付いた注釈
  （残したページと共有するフォームのウィジェット等）、ページツリーへの参照を切り離す
- 添付ファイル注釈（/FileAttachment）、関連ファイル（/AF）、埋込みファイル指定（/EFを持つ辞書）
  を除く。描画データ（ストリーム）はキーの有無で丸ごと除くことはしない
- ページ単位のXMPメタデータ（/Metadata）とアプリ固有データ（/PieceInfo）を除く
- 残したページ同士のリンクは、コピー後に出力したページへ付け替える
  （そのままでは、リンク先のページが表示されない複製としてもう1つコピーされるため）。
  付け替え用の目印は保存ごとの乱数を含む名前で、元PDFにある名前は書き換えない

継承されたResources等は、走査の前に各ページへ移してから確認します。
削除したページへのリンクは行先のないリンクになります。ページに付いたその他の
注釈・フォームの見た目は維持します。ページ間で共有している画像やフォント等は、
残したページが使っていればコピーされます。

この処理は作業ファイルのbase.pdfだけに適用しており、通常のPDF保存
（PDFを保存（全ページ）・選択を保存）は従来どおりです。

ファイル名は先頭ページの元ファイル名を基準に「元ファイル名.abpdf」とします。

四角・丸・テキスト・画像・手書き・ページ番号がある場合は、作業ファイルでは
図形を動かすと下の内容がそのまま見えることを確認メッセージで示します。
通常のPDF保存でも覆った下の文字は残っていてコピー・検索で取り出せるため、
含まれる情報量は変わりませんが、図形を外して見るのが容易になります。

作業ファイルの保存はダウンロード開始時点で保存済みとして扱い、
以後は閉じる・再読み込み時の確認を表示しません。保存後に編集すると
再び未保存になります。

読込み:

作業ファイルは、PDFを開いていない初期画面の「PDFを選択」・ドロップ・
貼り付けから開きます。PDFを開いている場合は、閉じてから開くよう案内します。
作業ファイルとPDFを混ぜた選択、複数の作業ファイルの選択は読み込みません。

作業ファイルは外部から来たファイルとして扱い、次を検証します。
いずれかに当てはまる場合は全体を読み込まず、開く前の状態へ戻します。

- ZIP: 無圧縮・暗号化なし・ZIP64なし・コメントなし、名前は project.json／base.pdf／
  images/番号.png|jpg だけ、重複なし、各項目が隙間なく並びヘッダーと一致、CRC一致
- 容量: ファイル全体約324MB、base.pdf 200MB、画像1枚20MB・合計100MB、
  project.json 20MB、ページ300、画像は各辺8192px・1600万画素
- 内容: 形式名・版、ページ数とbase.pdfの一致、図形の種類ごとの項目・型・範囲
  （色・線幅・文字サイズ・フォント・不透明度・座標・画像の参照と回転）、
  ページ番号・透かしの設定値と用紙への収まり、画像の形式・寸法の一致と使われていない画像の有無
- 件数: 図形1万件、手書き1本8192点・全体20万点、マーカーの矩形2万件、
  テキスト1件1万文字・全体50万文字

保存時も同じ検証と上限を適用し、開けない作業ファイルは作りません。
作業ファイル内の注釈ID・画像IDは使わず、読込み時に振り直します。
画像は再エンコードしないため、保存・読込みを繰り返しても画質は変わりません。


■ 7. セキュリティとプライバシー


● セキュリティとプライバシー

共有されたアプリコードでは、入力PDF、図形、編集済PDFを
次へ送信・保存する処理はありません。

- 外部API
- 外部クラウド
- 外部CDN
- IISへのファイルアップロード
- データベース
- localStorage
- sessionStorage
- Cookie

スタンプのテンプレートはブラウザに保存しません。利用者が明示的に
JSONファイルとして保存・読込みします。読み込んだテンプレートと入力内容は
タブのメモリ上だけに置き、PDFを閉じると消去します。テンプレートに氏名・所属名を
入れた場合、そのファイルの保管・共有範囲は利用者側で管理してください。

第三者ライブラリとCMapバンドルはvendorフォルダーから
同一オリジンで配信します。

web.configのContent-Security-Policyでは、原則として次を制限します。

- 外部スクリプト
- 外部スタイル
- 外部通信
- iframe
- object
- form送信

ただし、IISアクセスログには、通常のページアクセス情報や
静的ファイルの取得記録が残る場合があります。

入力PDFそのものをサーバーへアップロードする処理はありませんが、
端末、ブラウザ、ダウンロード先、クリップボード、バックアップ等の
取扱いは所属組織の情報セキュリティポリシーに従ってください。

● Content-Security-Policy

本ツールは、同一オリジン上のスクリプト、CSS、ES Module、
PDF.js WorkerおよびCMapバンドルを使用します。

基本方針:

- default-src: 自己オリジンを基本とする
- script-src: 同一オリジンのみ
- style-src: 同一オリジンを基本とする
- worker-src: 同一オリジンおよび必要なBlob Worker
- connect-src: 同一オリジンの必要な静的ファイル取得だけを許可
- img-src: 同一オリジンおよび必要なdata、blobを許可
- object-src: 禁止
- frame-src: 禁止
- frame-ancestors: 埋込み禁止
- form-action: 禁止

CMapバンドルはfetch()で同一オリジンから取得するため、
connect-srcで自己オリジンの取得を許可する必要があります。

HTMLにインラインstyle属性は使用しません。
フォント選択肢の見本は外部CSSのクラスで指定します。

JavaScriptは、PDF表示、図形の位置、寸法、色およびフォント等を
DOMのstyleプロパティへ動的に設定します。

実際のCSPは、配置先のIISとMicrosoft Edgeで動作確認してください。

PDF.jsの配布構成がWASM、標準フォントデータ等を追加取得する場合は、
必要なファイルを同一オリジンへ配置し、最小限の許可だけを
追加してください。


■ 8. アクセシビリティと操作性


実装している主な配慮:

- 操作ボタンへラベルまたは説明を設定
- 図形ツールへaria-pressedを設定
- 太字ボタンへaria-pressedを設定
- フォントメニューへlistboxおよびoptionの役割を設定
- フォントメニューを矢印キー、Home、End、Enter、Space、Escapeで操作可能
- ページ一覧をキーボードで選択可能
- ステータスとトーストへaria-liveを設定
- 処理中状態へaria-busyを設定
- 視覚的な処理中オーバーレイの読み上げを抑制
- キーボードフォーカスを表示
- Windowsハイコントラストモードを考慮
- 動きを抑える設定を考慮

制約:

- PDF本文のアクセシビリティは元PDFとPDF.jsに依存します
- 保存したテキストは画像のため、スクリーンリーダーで文字として読めません
- サムネイルのドラッグ＆ドロップ操作は、タッチ・キーボード環境で制限される場合があります
- 代替操作として「前へ」「後ろへ」ボタンを使用できます


■ 9. 既知の制約


- パスワード保護PDFは対象外です
- 暗号化PDFは対象外です
- 既存PDF本文の文字列は直接編集できません
- 正式な墨消し機能はありません
- CropBox、MediaBox、回転情報等が特殊なPDFでは位置がずれる可能性があります
- 一部のPDFはPDF.jsで表示できてもpdf-libで保存できない場合があります
- 必要なCMapがバンドルにないPDFは表示できない場合があります
- 壊れたPDFや仕様外PDFは読み込めない場合があります
- 非常に大きいスキャンPDFは多くのメモリを使用します
- 元PDFの高度な機能が保持されない場合があります
- PDF保存処理を途中でキャンセルする機能はありません
- 作業内容の自動保存・復元機能はありません
- ブラウザを閉じる、再読込みする、PDFを閉じる操作で未保存内容は失われます


■ 10. 運用・保守


本READMEのv1.2.0は、対応するindex.html、app.css、app.js、
web.config、vendorファイルおよびCMapバンドルとの組合せを前提とします。

FIX後にいずれかのファイルを変更した場合は、次を実施してください。

- 変更理由と変更箇所を記録する
- ファイルの版番号またはキャッシュ識別子を更新する
- SHA-256を再取得する
- 関連する本番配置前確認を再実施する
- Console、CSPおよびNetworkを再確認する
- READMEとライセンス資料を必要に応じて更新する

正式運用へ移行する前に、承認済みのテストPDFを使用して
本README「■ 11. 本番配置前の確認」を実施してください。


■ 11. 本番配置前の確認


● 本番配置前の確認

ファイル:

- index.html、app.css、app.jsが同じ版である
- vendorファイルが指定バージョンである
- cmaps.bundle.json.gzが配置されている
- SHA-256が記録値と一致する
- ライセンス原文が同梱されている
- .mjsおよび.gzの配信設定が正しい
- CMapバンドルに必要なCMapが含まれている

ブラウザ:

- Microsoft EdgeのConsoleに構文エラーや重大なエラーがない
- CSP違反がない
- PDF.js Workerが正常に起動する
- cmaps.bundle.json.gzを正常に取得・展開できる
- Networkに想定外の外部通信がない
- ブラウザキャッシュ更新後も同じ版のCSSとJavaScriptが読み込まれる

PDF読込み:

- 1ファイル100MB超を拒否する
- 合計200MB超を拒否する
- 300ページ超を拒否する
- パスワード保護PDFを拒否する
- 暗号化PDFを拒否する
- 破損PDFを拒否する
- 同時に選択した複数PDFの途中で失敗した場合、全体を読込み前へ戻す
- 追加読込み失敗時、追加前の状態へ戻す
- 失敗後に同じファイルを再選択できる
- 初回読込み中に処理中表示が見える
- 編集画面での追加読込み中に画面全体の処理中表示が見える
- 日本語CIDフォントを使用したPDFが表示される
- 縦書きPDFが表示される
- 必要なCMapがない場合に分かりやすいエラーが表示される

ページ:

- サムネイルをクリックして選択できる
- Enter・Spaceでサムネイルを選択できる
- 前ページ・次ページボタンが動作する
